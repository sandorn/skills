# 正话优化——文档去冗余参考

对已有 md 文档做精简优化时遵循此模式。核心原则：**减优于加，合并优于并列，具体优于冗余。**

## 四刀法

### 1. 删除冗余浓缩段落

长段落若内容与后续章节 1:1 重复（常见于文档开头的"本文涵盖……"），直接删除。
读者往下翻自然会看到，不需要摘要先行。

```
❌ "脚本使用 PENDING_KEY 跨页面状态机制。常见故障：①...②...③..."
   → 后面有完整的三节排查指南，与这句完全重复
✅ 压缩为一句核心架构描述 + "详见排查章节"，不再枚举
```

### 2. 合并碎片小节

仅 1-2 行或 1 句话独占一节的，并入相邻父节或相关节。

```
❌ ### 防自动更新配置        ← 仅 2 行代码
   ### 更新脚本              ← 仅 1 句话
✅ 并入 ### 脚本维护记录 末尾，作为子内容
```

### 3. 剥离项目特定信息

通用模板（如代码模式、排查流程）中的项目特定案例，移到各自项目的文档中，
模板只保留模式骨架。

```
❌ 通用 userscript PENDING_KEY 模板末尾挂着"番茄同步助手 v1.0.4 修复"案例
✅ 剥离案例到项目自己的调试指南，模板只保留模式 + 坑点表
```

### 4. 精简代码注释

代码示例只保留**关键警告**（会出错的那种），删除"解释代码在做什么"的注释。
代码本身应该自解释。

```js
// ❌ 过度注释
GM_setValue(PENDING_KEY, null);  // 立即清除 PENDING_KEY 的值
                                 // 这样可以防止页面刷新时重复执行
                                 // 这是一个关键的防护措施

// ✅ 只留警告
GM_setValue(PENDING_KEY, null);  // 立即清除，防重复触发
```

## 最终检查

优化完后问自己：
- 还有没有一句话独占的小节？→ 合并
- 有没有段落和后面章节大面积重复？→ 删除
- 通用模板里有没有特定项目名/文件路径？→ 剥离
- 注释是否在"解释代码"而非"警告坑点"？→ 精简
