# 3 轮自检详细协议

> Layer 2 硬性执行规则。Hook `check_draft_quality.py` 执行结构性检查，本文档定义 Claude CLI 的深度语义检查标准。

---

## Round 1: 人物行为 OOC 检查

**检查目标**: 确保所有角色行为、对话、选择与其人设一致。

**检查方法**:
1. 读取 `state-files/characters.json`，提取本章出场角色的完整档案
2. 逐段检查初稿中该角色的行为是否与以下字段冲突:
   - `personality_traits`（性格特征）—— 胆小者不应主动冲锋
   - `core_values`（核心价值观）—— 正义角色不应无故滥杀
   - `bottom_lines`（底线）—— 突破底线需要铺垫，不可轻易触发
   - `speech_style`（说话风格）—— 话风突变即为 OOC
   - `cultivation`（修为）—— 修为决定能力上限，不可超战力发挥
3. 允许的例外: 角色成长弧线中的渐变（需在细纲中明确标注）

**判定标准**:
- 任一行为与人设冲突 → 标注 OOC 点位 → 纳入 `revision_instructions`
- 3 处以上 OOC → 强制重生成

---

## Round 2: 剧情/伏笔执行检查

**检查目标**: 验证初稿完整执行了细纲中的关键剧情点和伏笔要求。

**检查方法**:
1. 将 `chapter_outline` 拆分为关键剧情点列表（按编号或分号分句）
2. 逐条在初稿中检查是否被覆盖
3. 检查 `foreshadowing.json` 中标记为 `unresolved` 且 `expected_payoff_window` 覆盖本章的伏笔
4. 验证伏笔在正文中是否被推进（暗示/部分揭示/回收）

**判定标准**:
- 关键剧情点覆盖率 < 80% → 纳入 `revision_instructions`
- 本章窗口期的伏笔完全未涉及 → 纳入 `revision_instructions`
- 覆盖率 < 50% → 强制重生成

---

## Round 3: 逻辑/战力/设定冲突检查

**检查目标**: 确保无战力崩坏、设定自相矛盾、逻辑漏洞。

**检查方法**:
1. 对比 `power_system.json` 中的:
   - `combat_rules`（战斗规则）—— 跨大境界战斗是否有合理解释？
   - `realms`（境界定义）—— 角色能力是否超出当前境界？
   - `equipment_ranks`（装备等级）—— 装备能力是否越级？
2. 对比 `world_setting.json` 中的:
   - `factions`（势力）—— 势力行为是否符合其立场和实力？
   - `geography`（地理）—— 位置移动时间是否合理？
   - `magic_items`（法宝）—— 法宝能力是否已有设定？
3. 检查本章内部逻辑一致性:
   - 前文建立的条件是否在后文被遵守？
   - 战力数字是否前后一致？
   - 时间线是否合理？

**判定标准**:
- 任一战力/设定冲突 → 标注并提供修正建议 → 纳入 `revision_instructions`
- 冲突涉及主线逻辑 → 强制重生成

---

## 重生成循环控制

```
第 1 次生成 → 3 轮自检 → 不达标:
  → 汇总所有 issues → revision_instructions
  → 调用 generate_draft(retry_count=1)
  → 再次 3 轮自检 → 仍不达标:
    → 简化修订指令（仅保留最高优先级 issues）
    → 调用 generate_draft(retry_count=2)
    → 仍不达标 → 标记"需人工介入"，输出当前最佳版本
```

- **最大重试次数**: 2 次（即总共最多 3 次生成）
- **超限处理**: 选择 3 个版本中通过检查项最多的一个，标注未解决的问题，交给用户决策
- **降级策略**: 第 2 次重试时仅保留 Round 1（OOC）和 Round 3（逻辑冲突）的检查项，放宽 Round 2（文案覆盖）

---

## 润色开关判定

以下场景自动跳过润色（直接使用 DeepSeek 初稿）:
- 过渡章节: 大纲中仅含 "前往XX" "赶路" "休整" 等移动/日常描述
- 纯信息章节: 大纲中仅含说明性内容（设定讲解/回忆杀/背景交代）
- 当前章节 < 第 3 章（开头章节建议先积累设定，统一润色）

用户可随时通过 `.env` 中的 `AUTO_SKIP_POLISH=true/false` 覆盖此行为。
