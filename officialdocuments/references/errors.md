# 公文写作 — 常见错误与修正

## 速查表

| # | 错误类型 | 典型症状 | 修正方向 |
|---|----------|----------|----------|
| 1 | 文种叠用 | "请示报告"连用 | 择一 |
| 2 | 文种错配 | 对不相隶属机关用请示 | 改用函 |
| 3 | 方向错误 | 下行用请示 / 上行用通知 | 按行文方向重选 |
| 4 | 一文多事 | 请示含多个独立事项 | 拆分 |
| 5 | 依据缺失 | "根据工作需要"无具体文件 | 引用文号或标"待核实" |
| 6 | 结尾错误 | 请示用报告结尾、函用请示结尾 | 按文种匹配结尾 |
| 7 | 数据模糊 | "大约""可能""左右" | 精确值或"XX"占位 |
| 8 | 对话式前言 | "好的，根据您的要求……" | 直接正文开始 |
| 9 | 标点滥用 | 感叹号、省略号、反问句 | 陈述句 |
| 10 | 版式未验证 | 只说"已生成 docx"但未做 8 项质量门检查 | 按 format-spec.md 逐项验证并出报告 |

## 一、文种混用

### 错误1：请示报告叠用

| 项目 | 内容 |
|------|------|
| **错误** | 标题"关于申请追加预算的请示报告"，结尾"以上请示报告当否，请批复" |
| **诊断** | 请示与报告不得叠用；根据结尾"请批复"应选请示 |
| **修正** | 标题"关于申请追加预算的请示"，结尾"妥否，请批示" |

### 错误2：向不相隶属机关用请示

| 项目 | 内容 |
|------|------|
| **错误** | 向市发改委发"关于申请项目立项的请示" |
| **诊断** | 发改委与公司不相隶属，不能用请示 |
| **修正** | 改用"函"，标题"关于申请XX项目立项的函"，结尾"可否，请函复" |

### 错误3：下行文用请示

| 项目 | 内容 |
|------|------|
| **错误** | 向下级发"关于要求子公司报送材料的请示" |
| **诊断** | 向下级发文不能用请示 |
| **修正** | 改用"通知"，结尾"特此通知" |

---

## 二、依据缺失

| 项目 | 内容 |
|------|------|
| **错误** | 仅写"根据工作需要"，缺乏具体文件支撑 |
| **修正** | 引用具体文件，如"根据《XX关于深化改革的指导意见》（XX〔2026〕X号）"；暂不确定时标注"待核实" |

---

## 三、一文多事

| 项目 | 内容 |
|------|------|
| **错误** | 一份请示含"追加预算""调整组织架构""调整班子分工"三个独立事项 |
| **诊断** | 违反一文一事原则 |
| **修正** | 拆分为三份独立请示 |

---

## 四、结尾用语对照

| 文种 | 错误结尾 | 正确结尾 |
|------|----------|----------|
| 请示 | "以上报告如无不妥，请审阅" | "妥否，请批示" |
| 报告 | "妥否，请批示" | "以上报告如无不妥，请审阅" |
| 函 | "妥否，请批示" | "如蒙同意，请即函复" / "可否，请函复" |
| 建议书 | "妥否，请批示" | "以上建议请审阅" |
| 检查报告 | "妥否，请批示" | "请按整改要求落实"（下行）/ "以上报告请审阅"（上行） |

---

## 五、数据表述模糊

| 项目 | 内容 |
|------|------|
| **错误** | "营业收入大约XX万元""利润可能增长XX%左右" |
| **诊断** | 使用"大约""可能""左右"等模糊用语 |
| **修正** | 使用精确数据或"XX"占位——"实现营业收入XX万元，同比增长XX%" |

---

## 六、格式与前言

| 项目 | 内容 |
|------|------|
| **错误** | 正文前添加"好的，根据您的要求，现起草请示如下："等对话式前言 |
| **诊断** | 公文中不得出现提示词、口语化前言 |
| **修正** | 直接从标题和正文开始，删除所有前言 |

---

## 七、版式验证遗漏

| 项目 | 内容 |
|------|------|
| **错误** | 生成 docx 后只说"已生成"，未检查字体、字号、页边距、缩进、行距 |
| **诊断** | 仅 pandoc 裸转或未按 `format-spec.md` 质量门验证 |
| **修正** | 按 `format-spec.md` 8 项逐项验证，解压 docx 检查 XML；回复中附验证报告 |

---

## 八、行文关系

| 错误 | 正确 |
|------|------|
| 平行机关用请示 | 改用函 |
| 下级对上级用通知 | 改用请示或报告 |
| 上级对下级用请示 | 改用通知或批复 |

## 九、脚本层已修复的缺陷（勿回退）

以下三处曾导致**格式正确的文档被误判、或正确文档被排错版**，均已修复。改动脚本时勿回退。

### 缺陷1：正文引用条款破坏编号（gb_gongwen.py）

| 项目 | 内容 |
|------|------|
| **症状** | 报告类公文中，二级编号出现"（一）（一）（二）（一）"错乱 |
| **根因** | `ART_RE` 用 `search()` 匹配正文**任意位置**的"第X条"。正文引用制度条款（如"依据《XX办法》第七条""按第十二条要求"）被误判为制度条文边界，重置了二级/三级计数器 |
| **修正** | `ART_RE` 锚定行首 `^第[X]条(?=[\s　]|$)`，调用改为 `ART_RE.match(text.lstrip())` |
| **验证** | 报告类正文含"第七条"引用时编号连续；制度类"第一条 xxx"仍正确重置 |

> 教训：制度条文边界必须**行首锚定**。引用条款是正文的正常表述，不是结构标记。

### 缺陷2：一级标题不被识别为分节边界（qa_docx.py）

| 项目 | 内容 |
|------|------|
| **症状** | 每节二级编号从"（一）"重启的**正确**公文，被报"编号不连续，期望（五）" |
| **根因** | 检查器只把"第X条"当分节边界（为制度类设计），不认"一、二、三"一级标题，于是把全文二级编号当作一条连续序列 |
| **修正** | 新增 `H1_OUT_RE`，"一、xxx"同样重置 h2/h3 计数器 |
| **副产物** | 报错信息中的"第0条区间"恒为0，修正后正确显示"第1节/第2节区间" |

### 缺陷3：表格数字被误判为编号（qa_docx.py）

| 项目 | 内容 |
|------|------|
| **症状** | 报"三级编号错误：期望 1．实际112.84万元"、"期望 113．实际363.07万元" |
| **根因** | 检查器提取全部 `<w:t>`（含表格单元格），金额"112.84万元"匹配了 `^\d+[．.]` |
| **修正** | 新增 `_extract_body_texts()`，仅遍历 `<w:body>` 直接子级的 `<w:p>`，整体跳过 `<w:tbl>`；`H3_OUT_RE` 加 `(?!\d)` 排除小数 |
| **附带收益** | 按 `<w:p>` 取整段文本后，原先靠标点猜测段落边界的 run 合并启发式逻辑被删除，更健壮 |

> 教训：编号连续性只针对正文段落。表格里的金额、比率、行号不是编号。

### 排查方法

编号异常时，先用解析层定位，不要盲改 md：

```bash
python -c "
import sys; sys.path.insert(0,'<skill>/scripts')
from gb_gongwen import markdown_to_parts, ART_RE
for p in markdown_to_parts(open('稿件.md',encoding='utf-8').read()):
    if p[0] in ('14','15','16'): print(p[0],'|',p[1][:40])
    elif p[0]=='19' and ART_RE.match(str(p[1]).lstrip()): print('!!RESET:',str(p[1])[:50])
"
```

看到非预期的 `!!RESET` 即为边界误判。**质检报错时先判断是文档问题还是检查器误报**——用负向样例（故意跳号）确认检查器仍有效，再决定改文档还是改脚本。
