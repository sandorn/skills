# 甲方视角内部管理制度起草指导

## 适用范围

为甲方（业主/委托方）起草对委托运营方（乙方/承包方）的管理制度，而非代替运营方起草其内部操作规程。

## 核心原则

### 1. 甲乙方边界识别矩阵

起草每项制度前，先回答三个问题：

| 问题 | 应写入制度的 | 不应写入制度的 |
|------|-------------|---------------|
| 甲方做什么？ | 检查、考核、结算、验收、准入评价、投诉处理 | — |
| 乙方做什么？ | **只写标准**（"须持有效健康证上岗"），**不写操作**（"如何办理健康证"） | 操作流程、内部排班、岗位职责描述、作业指导书 |
| 日常落地动作量？ | 必须预估并控制，体现"正确废话"风格 | 超出人员配置能力的冗余流程 |

### 2. "正确的废话"原则

制度的绝大多数内容应是"标准线"而非"操作手册"：
- ✅ 写"运营方应建立食品安全管理制度"（定标准）
- ❌ 写"食材应洗净后切配，切配台每日消毒"（代乙方写SOP）
- ✅ 写"分公司对运营方实行考核"（定动作）
- ❌ 写"每月5日前收集各部门意见，10日前汇总评分"（代甲方写流程，人员少时做不到）

### 1b. 惩戒力度原则——"过罚相当"

**核心思想：以督促整改为目的，处罚为辅；区分违规轻重、首次与多次不同对待。**

制度中涉及罚款/处罚的条款，应体现梯度化处理，不宜一刀切。推荐采纳以下形式：

```
轻微违规 → 首次书面提醒，不罚款；再次发生按标准处罚
一般违规 → 首次书面提醒+限期整改；再次发生按标准处罚
严重违规 → 直接按标准处罚+限期整改
重大违规 → 从重处罚，承担全部损失及法律责任
```

**理由**：① 体现甲方管理专业性，不是以罚代管；② 首次提醒给了运营方改进机会，减少对抗；③ 梯度清晰，实际执行时争议少。

### 2a. 微型甲方团队（≤3人）特别处理

当甲方本身人员极少（2-3人）、没有部门划分时，制度起草需进一步精简——**让制度看起来像"正确的废话"，因为人很少，太多落地动作执行不了**。

**部门代词统一规则：**

文中所有"综合管理部门""财务部门""行政部门""人事部门"等，**统一改为实体名称**（"分公司""公司"），职责合并列举，不分部门逐一写。例如：

| 常见初稿写法 | 微型团队修正 |
|-------------|-------------|
| 综合管理部门负责监督检查 | 分公司负责监督检查 |
| 由综合管理部门和财务部门按职责分工共同解释 | 由分公司负责解释 |
| 成员包括XX部、XX部及员工代表 | 根据工作需要协调就餐单位代表参与 |

**审核链条最短化规则：**

跳过部门层级批审，直接到"分公司负责人审批"或"分公司审核"。不出现"经XX部门初审→XX部门复核→公司领导审批"的多级链。

**"弹性表述"优先于"硬性时限"原则：**

| 硬性表述（小团队执行困难） | 弹性表述（降低执行压力） |
|--------------------------|------------------------|
| 每月25日前报送次月采购计划 | 遇市场价格重大变化时报送 |
| 每周不少于两次巡查 | 根据工作实际，定期或不定期开展 |
| 每月一次全面考核 | 按周期进行考核 |
| 每季度组织一次满意度调查 | 定期组织满意度调查 |
| 考核结果5个工作日内通知 | 考核结果适时通知 |
| 运营方3个工作日内申诉 | 运营方可提出书面申诉 |
| 保存不少于2年/5年（分类写死） | 保存期限遵循法律法规及总公司的相关规定 |

**边界自检快速判断表（新增）：**

起草制度时，甲方最常自我怀疑的问题是：**"这个制度是不是太细了？是不是侵犯了乙方的责任边界？"**

以下清单帮助快速判断。如果"是"的回答≥2个，说明应走**考核标准路线**而非单独发制度：

| 自检问题 | 应单独发制度（YES） | 应纳入考核标准（NO） |
|---------|-------------------|-------------------|
| 这个制度是写"甲方怎么管"还是"乙方怎么做"？ | 甲方怎么管 | 乙方怎么做 |
| 内容本质是定标准还是写操作手册？ | 定标准（"须持有效健康证"） | 写操作（"如何办理健康证"） |
| 是否有刚性的合规依据（法规强制要求甲方制定）？ | 有 | 无（或可转由乙方自行制定） |
| 制度发布后甲方需要做什么具体动作？ | 考核/结算/准入评价等甲方动作 | 检查/抽查即可（例：检查健康证是否有效） |

**典型越界案例（不应由甲方发独立制度）：**

| 制度名 | 越界原因 | 正确处理 |
|--------|---------|---------|
| 食品安全操作规范 | 替运营方编写其核心业务SOP | 在监督考核维度的"食品安全管理"中写检查项 |
| 从业人员健康与卫生管理制度 | 法规要求运营方建立，甲方监督即可 | 考核标准中列入"从业人员健康管理"维度 |
| 环境卫生与消杀管理制度 | 运营方的日常保洁属于其合同义务 | 考核维度+合同责任条款即可，不单独发文 |

### 3. 制度结构

内部管理制度采用章/条结构（第X章/第X条），非公文六要素：

```
# 制度名称

## 第一章 总则
第X条 目的依据
第X条 适用范围

## 第二章 具体规定
第X条 ...
第X条 ...

## 第三章 附则
第X条 解释权
第X条 施行日期
```

如需以通知形式印发，另加印发通知作为封面，制度正文作为附件。

### 4. 评分细节下沉原则

**核心规则：得分计算方式、等级区间、具体扣分标准、等级分值区间不写入制度正文。**

制度正文写"检查什么""怎么评""结果怎么用"；得分公式、等级分值、罚款金额等机械性细节全部放入附件量化表。

| 应写入正文（框架性） | 不应写入正文（下沉到附件） |
|---------------------|--------------------------|
| 检查考核涵盖XX维度 | 每个维度多少分、扣分标准 |
| 考核结果分四个等级 | 优秀/良好/合格/不合格的得分区间 |
| 违规罚款按量化表执行 | 轻微/一般/严重各罚款多少元 |
| 运营方享有申诉权利 | 申诉时限N个工作日、复核时限N个工作日 |

**原因**：① 得分数值、等级区间可能在合同谈判中调整，写入正文需同步修订制度，降低灵活性；② 正文保持简洁，专注管理逻辑；③ 附件量化表作为合同附件，甲乙双方签字确认，法律效力同等但修订路径更短。

### 4b. "考核"与"评分"分离架构

制度正文与附件量化表采用"考核逻辑"与"评分细则"分离的两层结构：

```
制度正文（框架层）                附件量化表（执行层）
┌─────────────────────┐          ┌──────────────────────────┐
│ 检查考核涵盖XX维度    │          │ 食品安全 违规情形1 → 50元 │
│ 违规分四个等级        │          │         违规情形2 → 100元│
│ 遵循"首次提醒、再次   │          │ 服务质量 违规情形1 → 50元 │
│  处罚"原则           │  引用→   │         违规情形2 → 100元│
│ 一票否决情形          │          │ ……                      │
│ 申诉复核程序          │          │ 考核说明（首次不罚原则等）│
└─────────────────────┘          └──────────────────────────┘
```

**正文中仅保留**：管理逻辑、边界定义、程序性规定（申诉/复核/一票否决）
**下沉到附件**：具体分值、罚款金额、扣分标准、等级得分区间

### 4c. "一票否决"条款的正文定位

**一票否决/直接不合格条款必须保留在制度正文中**（不下沉到附件），因为：
- 它们代表甲方的**管理边界决策**，非机械性扣分
- 通常涉及人身安全、重大财产损失或合同解除权
- 具有法律/合同层面的重要性，不宜隐藏在附件中

典型的一票否决情形示例（写入正文）：
```
发生以下情形之一的，当期考核直接计为不合格，并依据合同追究违约责任：
（一）发生食品安全事故，导致人员食物中毒或其他食源性疾病的；
（二）发生火灾、燃气泄漏等安全事故，造成人员伤亡或重大财产损失的；
（三）连续两个考核周期考核结果为不合格的；
（四）故意隐瞒重大违规行为、销毁证据或阻挠检查的。
```

### 4d. 考核结果引用未生效协议条款的陷阱

**P0 级错误：制度正文写"具体挂钩比例在委托管理协议中约定"，但委托管理协议尚未确认包含该条款。**

```
❌ 错误：
  第十四条 考核结果与服务费结算挂钩。具体挂钩比例在委托管理协议中约定。
  → 委托管理协议未包含该条款时，制度成为"悬空条款"，无法执行

✅ 正确做法之一（自含条款）：
  考核结果与服务费结算挂钩。具体挂钩比例由双方协商确定后执行。

✅ 正确做法之二（确认后引用）：
  仅写"考核结果纳入服务费结算参考"，不承诺具体挂钩比例。
```

**自检**：制度中所有引用外部文件（委托管理协议、总公司制度等）的条款，须确认该文件确实包含所引用的内容。无法确认时，使用自含条款或模糊表述。

### 4e. 篇幅扩充方法（不增加甲方动作）

当制度篇幅不足（如预期3页但仅1.5页），**不能通过新增执行动作来凑字数**。应采用以下"正确废话"技术扩充：

| 技法 | 做法 | 示例（从→到） |
|:----|:----|:-------------|
| **章拆分** | 将原本一章拆为两章 | 原"资产范围与登记"一章 → 拆为"资产范围与分类"+"资产登记与台账"两章 |
| **原则章节扩充** | 总则中增加原则条款 | 原无管理原则 → 增加"产权清晰、台账健全""谁使用谁维护、谁损坏谁赔偿""定期盘点、规范处置"三条原则 |
| **定义细化** | 对分类/等级增加定义描述 | 原"固定资产——厨房设备等" → 增加分类标准："使用年限较长、价值相对较高""价值较低、更换较为频繁" |
| **程序步骤展开** | 将程序展开为步骤式描述 | 原"投诉按程序处理" → 展开为"登记受理→核实情况→明确责任→处理落实→结果反馈→归档记录"六步，每步一句话 |
| **原则性补充** | 在关键节点加原则性声明 | 原"财务处理按规定" → 补充"做到事实清楚、定性准确"或"确保处理结果经得起各方检验" |
| **弹性程序定义** | 用"适时""定期""按需"等弹性词展开 | 原"分公司检查" → 展开为"根据工作实际，定期或不定期对食堂进行现场检查，重点关注……" |

**扩充效果对照**（单篇制度）：

| 扩充前 | 扩充技法 | 扩充后 | 甲方动作增量 |
|:-----:|:--------:|:-----:|:----------:|
| 638字 | 拆分章节+原则章节+定义细化+程序展开 | 1167字 | 0（无新增） |

**核心准则**：扩充后的总字数增加但甲方执行动作量增加为**零**。

### 4a. 等级区间边界 P0 级陷阱——分数重叠

**这是制度起草中最容易犯的 bug，一旦命中会导致考核结果无法确定。**

错误写法（分数重叠）：
```
合格    70分至79分    基本达标，限期整改
不合格  70分以下      启动违约处理程序
```
→ **70分同时属于"合格"和"不合格"，出现归属歧义。**

正确写法（边界唯一）：
```
合格    70分至79分    基本达标，限期整改
不合格  低于70分      启动违约处理程序
```
或：
```
不合格  69分及以下    启动违约处理程序
```

**自检规则**：所有等级区间的上下界必须互斥且全覆盖。随机取每个区间的端点值（如69、70、71、79、80、89、90），算出来唯一归属一个等级，才算通过。

**一句话记忆口诀**：写下限时用"不低于/及以上"，写上限时用"低于/未满"，绝不写"XX分以下"与"XX分至YY分"在同一个端点重叠。

### 5. 篇幅控制

| 制度类型 | 建议篇幅 | 说明 |
|---------|:-------:|------|
| 总则/纲领性制度 | 3-4页（15-20条） | 一次性定稿，无日常动作 |
| 核心管理制度（考核/合同） | 4-6页（20-30条） | 有周期性动作，需写清程序 |
| 专项制度（投诉/资产/档案） | 2-3页（10-15条） | 轻量级，例外时启用 |
| 应急预案 | 3-4页 | 平时不碰，出事才用 |

## 典型制度清单模板（食堂场景）

| 层次 | 制度 | 日常动作量 |
|:---:|------|:---------:|
| 纲领 | 运营管理总则 | 无 |
| 核心 | 监督与检查制度 | 月度半天 |
| 核心 | 供应商管理办法 | 年度半天 |
| 接口 | 采购与验收管理办法 | 每日5分钟 |
| 接口 | 投诉与反馈制度 | 季度10分钟 |
| 保障 | 资产与设备管理制度 | 半年半天 |
| 保障 | 合同与档案管理制度 | 归档一次 |
| 保障 | 食品安全应急预案 | 不出事不动 |



## 常见误区

| 误区 | 错误做法 | 正确做法 |
|------|---------|---------|
| 越界代庖 | 替运营方编写食品安全操作规范、卫生管理制度 | 在考核标准中写入"食品安全管理"维度 |
| 过细流程 | 规定每月N号做什么、每季度N号做什么 | 只写"定期""按实际需要"等弹性表述 |
| 忽略甲方动作量 | 制度设定了复杂的审批/备案/报告流程 | 每项制度末尾标注日常落地动作量 |
| 公文格式错配 | 用"请示""报告"格式写内部制度 | 用第X章/第X条结构 |
| 考核小组写死组成 | 规定"成员包括XX部门XX代表"——小团队无法固化成员 | 用弹性措辞"可根据工作需要协调XX代表参与" |
| 报销/采购环节写死时限 | "每月X日前报送"——小团队没有专人跟进 | 用"遇重大变化时""按需"等触发式表述 |
| 档案保存年限写死 | "保存不少于2年/5年"——分类过细无法落实 | 统一"遵循法律法规及总公司的相关规定" |
| 引用不存在的协议条款 | 制度正文写"具体挂钩比例在委托管理协议中约定"但协议中无此项 | 要么确认协议已包含该条款再引用，要么在制度的附则中自含规定，不依赖外部未定条款 |

### 交付方式

- Markdown 草稿：直接写入工作目录，供用户审阅
- Word 正式版：经用户确认后，可用 `scripts/gb_gongwen.py` 导出为可报送版式（注意：脚本预设的是公文版式，内部制度如需正式排版需调整页边距/标题字体等参数）

## 常见陷阱

### 陷阱一：假性委托（虚假交叉引用）

```markdown
❌ 错误：考核结果与服务费结算挂钩。具体挂钩比例在委托管理协议中约定。
```

如果委托管理协议**实际上没有**约定挂钩比例，这条就是空话，既不能执行也无法追责。

✅ 正确做法：在起草任何声称"具体在XX协议/合同中约定"的条款前，先确认该协议/合同**确实包含该内容**。如果不存在，要么直接写在本制度中，要么写为"由分公司与运营方另行协商确定"。

### 陷阱二：制度正文出现 Markdown 排版标记

`gb_gongwen.py` 生成的 docx 不会自动去除 Markdown 内联标记（如 `**`）。如果 md 文件中有 `**第一条**`，docx 中会原样出现星号。

✅ 当前 `gb_gongwen.py` 2.2.2+ 已内置 `_strip_markdown_inline()` 自动清理。如果自行在调用侧预处理，只需清理 `**` 即可，**不要**清理 `#`（公司名称作为制度标题头的一部分需要保留）。

### 陷阱三：`---` 分隔线残留

md 文件末的 `---` 分隔线如果被保留，会在 docx 中产生多余的空行或渲染为横线。`_strip_markdown_inline()` 已处理整行 `---`，但交叉引用的 `---`（如在附件前）不会被清理，应在最终排版前移除。
- **附件命名规范**：附件文件从工作目录复制到制度目录时应使用规范名称，如 `食堂运营违规处罚量化表.docx` 而非 `考核3(1).docx`。制度正文中引用附件名称应与实际文件名保持一致。
- **工作量估算表（推荐一并交付）**：制度定稿后，从各制度中提取甲方需执行的落地动作，输出一份"工作清单—频次—工作量"对照表，让用户直观看到每周/每月投入时间。微型团队（≤3人）总工作量建议控制在**每周约2小时以内**，超出需协商简并。
