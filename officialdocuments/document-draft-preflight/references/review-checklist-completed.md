# 制度审查清单 — 对已完稿制度的审查要点

> 本清单服务于**用户已有一份制度稿，要求审查/把关/提意见**的场景。
> 与 `document-draft-preflight`（起草前前置检查）互补：那个是动手前问，这个是写完后查。

---

## 一、前置检查：版本谱系追溯（与起草前共享，但视角相反）

- [ ] 用 `search_files` 检索目标目录下是否有**旧版本**、**在推稿**、**已发布版本**
- [ ] 如有旧版，**逐页对比**，识别本稿相比旧版的**实质性变化**（新增/删除/弱化/强化）
  - 特别关注：母公司报批路径是否弱化、审批权限是否放大、弹性措辞是否更松
- [ ] 如有平行制度（如"商业租赁"vs"写字楼租赁"），确认适用范围不重叠
- [ ] 上位制度（母公司/集团管理规定）检查：本稿是否越权、是否弱化上位要求
- [ ] 项目 `AGENTS.md` 中的特定约束（部门名称、人员规模、授权边界）是否被违反

---

## 二、结构与定位审查

- [ ] 制度定位是否清晰：管理办法（流程/权限/标准）vs 实施细则（具体操作）——正文不越界
- [ ] 章/条结构逻辑递进，无缺章、断头路
- [ ] 附件与正文一一对应，**附件不可为空壳**（如附表中额度全标"（另定）"）
  - **空壳陷阱**：附件声称"与正文具有同等效力"但额度全是"另定"——发布即无约束力。须给过渡性管控：要么同步发布，要么写明"未发布前一律按重要事项报批"
- [ ] **母本结构破坏检查**（T12）：母本原有条款在新稿中被拆入不同章时，附则第三十二条（废止条款）是否涵盖旧条款；被吸收条款是否在正文中已有等价规定。**典型表现**：旧版"续租扩租缩租"是单独一段，新版拆入第三章价格体系和第五章合同管理各一段——需确认没有漏项或歧义。

---

## 三、实体内容审查

### 3.1 权限与审批

- [ ] 审批层级是否闭环：一般事项/重要事项/一事一议三类，无遗漏
- [ ] 审批主体是否明确定义："有权人""相关领导"等模糊主体须有定义
- [ ] **权限倒挂检查**：一般事项（OA签批）最大放权幅度，是否超过了重要事项（上会）的体系调整幅度。如果倒挂→调整折扣上限或加"折扣后有效租金不低于体系底线"的兜底
- [ ] 母公司报批路径：对比旧版有无弱化；如有，须确认母公司现行授权清单允许
- [ ] **审批表述质量检查**：正文中的"XX的审批"（如"扩租按XX执行的审批"）是事项描述还是审批授权？统一改为"由XX审批"或"按XX办理"

### 3.2 数据与计算口径

- [ ] 所有百分比、折扣、公式：**计算基数是否统一**
- [ ] 多层折扣（标准折扣→二次下调→突破审批）：连乘/连加？累计上限？折扣底线≥体系底线？
- [ ] 公式变量单位统一（月/日/年），取值边界闭合（"不超过""不低于"）
- [ ] **同一个百分比的"原则上"必须有关闭路径**：无例外路径的"原则上"=敞开授权
- [ ] **价格体系双轨道审查**：区分"体系价调整"和"成交价折扣"两个层级。标准折扣叠加后上限（如15%）是否超过体系调整上限（如10%）？如果倒挂→要么放宽体系调整上限说明（改为"体系整体调整"），要么加"折扣后有效租金不低于体系规定下限"句子使二者闭环

### 3.3 合同衔接

- [ ] 制度中的**刚性数字**（逾期天数、违约金比例、保证金倍数、押付方式）与现行制式合同是否一致
  - 不一致时：如果是管理依据，须写"按合同约定"衔接语；如果是合同引用的标准，须对齐
- [ ] 制度赋予公司的权利（解除权、催告权）是否与合同匹配

### 3.4 弹性措辞审核（适用于"正确的废话"风格）

- [ ] 频次用"定期或不定期""适时"等弹性词，不用死数字
- [ ] "原则上"全部有例外路径（升级/一事一议），不留无路径开口

## 四、常见陷阱快速扫描

| 编号 | 陷阱 | 典型表现 | 检查方式 |
|------|------|----------|----------|
| T1 | 部门称谓不统一 | 正文"招商部门"vs旧版"招商运营部" | search_files全文 |
| T2 | 术语未定义 | "有权人""有效租金"出现但总则无定义 | grep全文 |
| T3 | 附件空壳 | 附件额度标"另定"但正文声称有同等效力 | 翻附件 |
| T4 | 自动升级无触发条件 | "出现突破→升级"但谁认定"突破"不写 | grep自动升级 |
| T5 | 价格体系双轨道 | 标准折扣叠加上限倒挂体系调整上限 | 对比第十/十四/十五条的基数与封顶 |
| T6 | 审批表述冗余 | "扩租部分按XX执行的审批"→应为"按XX执行" | grep".的审批" |
| T7 | 母公司报批弱化 | 旧版须报母公司批准，新版只写"涉及母公司审批权限的" | 对比附则与第八条 |
| T8 | 保密条款无法约束外部 | 内部制度要求外部主体保密 | 查第三十条附近 |
| T9 | 追溯适用被删除 | 附则无"旧合同按原合同执行至期满" | 查附则 |
| T10 | 废止范围过宽 | "凡与本办法不一致处一律废止"—可能废止平行制度 | grep"废止" |
| T11 | 附件空窗期未管控 | 附件额度未填列即发布=授权空窗 | 查附件说明末段 |
| T12 | 母本结构破坏 | 旧版条款被拆入新版不同章，附则未写废止对应关系，漏项 | 逐条对照母本每个段落→新稿找到对应条文 |
| T13 | **批量改动基线错误（静默回退）** | 术语统一/润色类批量改动跑在**旧基线**稿上：新版附件数据、附件定义被整体回退，已修正的语病被改回，同时悄悄引入新错字 | 任何批量改动**前后**都与**最新备份**做 diff（`scripts/docx_text.py` 抽文本 → `diff -u`）；出现净回退立即报告，不默认新稿更新 |
| T14 | 注释与数据脱钩 | 附件数据被整体替换成新体系后，注释仍写"本表与X版完全一致" | 数据替换后**逐条复读**全部注释/脚注/引用语是否仍成立 |
| T15 | 附件精简致公式失基准 | 附件删列（如删优免期/装修期列）后，正文公式与"载明要素"清单无据可依 | 把正文列出的"应载明要素"与附件实际列名逐项对齐，二者取一 |
| T16 | 正文未引用附件 | 附件清单列了附件N，正文通篇无一处引用；附件N又与正文条款重复表述 | `grep 附件[一二三四五]` 全文；无引用的附件要么补引用，要么下沉正文 |
| T17 | 部门称谓跨制度不一致 | 本稿用"财务管理部""法律顾问"，同批待审定制度用"财务部""法务部""行政部" | 横向 `search_files` 同目录其它制度取部门名，不一致处列确认项 |
| T18 | **删除型替换吞标点** | 以"…，按母公司要求办理。"整串替换为空，句末句号随子句一起消失 | 删除子句时 old 串不含句末标点；改完逐句复读标点 |
| T19 | **串联写成并联** | "母公司另有要求的事项，按其中最高权限层级一次性办理"——把母公司报批当成与总办会并列的层级 | 把审批链画出来（OA→总办会→报母公司），串联一律写"先…再…"；佐证看议事规则职权条 |
| T20 | **表格宽度声明与实际渲染不符** | `tblW=pct` 看着是"100% 版心"，但 `tblLayout=fixed` 下 WPS/Word 按 `tblGrid`+`tcW` 里的**绝对列宽**渲染，仍超出右边距 | 列宽一律用 `dxa`，把 `tblW`/`tblGrid`/`tcW` 三处对齐到版心宽度；用 WPS COM 实测 `Documents.Tables(i).Columns(j).Width` 与"版心=页宽−左右边距"比对，别只看 XML |

---

## 五、输出格式

1. 列出**实质性必改项**（权限矛盾、口径冲突、颠覆性内容）
2. 列出**建议修改项**（文字、体例、优化）
3. 给出**修改优先级**（上会前/本轮修改/定稿排版时）
4. 如有空窗附件 → 给出**过渡性管控建议**
5. 推荐出清洁版改后正文 vs 仅出审查意见
