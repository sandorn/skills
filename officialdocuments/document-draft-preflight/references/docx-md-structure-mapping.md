# 制度类 md 结构 → `gb_gongwen.py` 标题层级映射

## 核心规则

`gb_gongwen.py` **不认 `#` 语法，靠中文编号识别标题层级**。喂入的 md 必须保留中文编号（编号值可任意，脚本会重排）。

| 脚本识别 | 正则 | 渲染为 | 用途 |
|---------|------|--------|------|
| `一、xxx` | `H1_RE = ^([一二三四五六七八九十]+)、\s*(.*)$` | 样式14 黑体三号 | **章** |
| `（一）xxx` | `H2_RE = ^（([一二三四五六七八九十]+)）\s*(.*)$` | 样式15 楷体三号 | **条** |
| `1. xxx` / `1．xxx` / `1、xxx` | `H3_RE = ^(\d+)[.．、]\s*(.*)$` | 样式16 仿宋三号加粗 | 三级标题（**参与全局三级编号**） |
| `第X条 xxx` | `ART_RE = ^第[一二三四五六七八九十百千]+条(?=[\s　]|$)` | 样式19 正文 + **重置二三级计数器** | 制度条文边界 |
| 其他 | 兜底 | 样式19 仿宋三号正文 | 正文 |

（`H1_RE`/`H2_RE`/`H3_RE` 在脚本约 112-114 行；`ART_RE` 约 97 行。）

## 推荐映射：章 → 一级标题，条 → 二级标题

```markdown
北京中言房地产开发有限公司        ← 第1行自动成为主标题(样式13)
采购管理办法（2026版）            ← 第2行会成为正文！须与第1行合并或另作处理

一、总则                          ← 样式14 黑体「一、总则」= 章

（一）目的与依据                  ← 样式15 楷体「（一）目的与依据」= 条
为加强……制定本办法。              ← 样式19 正文

（二）适用范围
本办法所称采购，是指……

二、采购方式

（一）采购方式分类
```

**效果**：章=黑体、条标题=楷体、条内正文=仿宋，层级清晰，无 Markdown 残留。

## 关键陷阱

### 陷阱1：条内款项禁用 `1.` 形式

`1. xxx` 会被当作**三级标题**（样式16）并参与**全局三级编号**（跨条连续递增）。

```markdown
错：                         对：
（四）术语定义                （四）术语定义
1. 采购组织部门：指……         （1）采购组织部门：指……
2. 采购需求部门：指……         （2）采购需求部门：指……
```

同样地，`（一）……（五）` 用于**条**时，条内并列项改用 `（1）……（5）`。

> 脚本手记亦提示：正文中的并列说明若不想进标题层级，改用"其一，""第一，"等表述。

### 陷阱2：正文行 `第X条` 会重置编号

`ART_RE` 锚定**行首**。因此若采用"条=二级标题（`（一）`）"映射，**不要再在正文中写行首的 `第一条 xxx`**——那会重置二三级计数器，导致后续 `（一）（二）` 从 1 重新开始。

两种映射二选一，不要混用：

| 方案 | 结构 md | 效果 |
|------|---------|------|
| **A（推荐）** | 章=`一、`，条=`（一）`，款项=`（1）` | 层级分明，无 ART 重置 |
| B | 章=`一、`，条=`第一条 xxx`（行首），款项=`（一）` | 依赖 ART 重置，条标题是正文样式（不突出） |

必要时在二级标题中引用条文序号（如"属于本办法公开招标规定情形的"），**避免行首写"第X条"**。

### 陷阱3：附件中的 `>` 引用块会泄漏

`_strip_markdown_inline()` 只清 `**` / `__` / `---`，**不清 `>`**。附件类文档写"注："时：

```markdown
错：                                    对：
> 注：1. 本需求单经……审批后……           注：
> 　　2. 采购方式分为……                  1. 本需求单经……审批后……
> 　　3. 采购需求发生实质性变化的……       2. 采购方式分为……
                                         3. 采购需求发生实质性变化的……
```

`qa_docx.py` 会报 `❌ 引用块 >: 检出 N 处` 并**阻断**（第一层以外唯一会阻断的 Markdown 残留项）。

### 陷阱4：主标题第二行会掉进正文

多行标题（公司名 + 制度名）须处理首行归属：

```bash
# 方案1：用 --title 指定完整标题，脚本会跳过首行
python gb_gongwen.py in.md out.docx --title "北京中言房地产开发有限公司采购管理办法（2026版）"

# 方案2：md 首行写成合并标题
# 北京中言房地产开发有限公司采购管理办法（2026版）
```

注意 `markdown_to_parts()` 逻辑：有 `--title` 时若 `lines[0]` 以 `#` 开头才跳过首行；否则**整个 body_lines 从第1行开始**。不传 `--title` 时取 `lines[0]` 为标题、body 从 `lines[1]` 开始。

### 陷阱5：制度类不传 `--author` `--date`

`--author` / `--date` 会在末尾插入落款（公司名+日期）。**内部管理制度不需要落款**，传了会出现多余的公司名与日期行。

### 陷阱6：二级标题超 10 项会退化成阿拉伯数字（脚本已修，2.3.2+）

旧版 `cn_num` 只覆盖 0-10，第 11 项起输出 `（11）（12）`，与前文 `（九）（十）` 不一致。`qa_docx.py` **不报错**，须人工 grep 自检：

```bash
# 标题行不应出现半角阿拉伯编号；正文款项（1）属正常
python -c "
import zipfile,re
x=zipfile.ZipFile(r'输出.docx').read('word/document.xml').decode('utf-8')
ts=[''.join(re.findall(r'<w:t[^>]*>(.*?)</w:t>',s,re.S)) for s in re.findall(r'<w:p>.*?</w:p>',x,re.S)]
print([t for t in ts if re.match(r'^（\d+）',t) and t.endswith(('职责','管理','委托','程序','结算','标准'))])
"
```

**长制度（某章二级标题 >10 个）必查。**

## 双体制：条标式 ↔ 章条式

用户常在产出后要求换编号体制。两者**内容完全相同，仅编号形式不同**，可从同一份源 md 转换，不要重写正文。

| 体制 | 标注形式 | md 写法 | 适用 |
|------|---------|---------|------|
| **条标式** | `一、总则` / `（一）目的与依据` / `（1）…` | 章=`一、`，条=`（一）`，款项=`（1）` | 内部制度、办法（默认） |
| **章条式** | `第一章　总则` / `第一条　…` / `（1）…` | 章=`第一章　总则`，条=`第一条　…` | 正式发文、需报审/备案 |

### 关键区别

- **章条式的「条」是正文段落**，条文标题与正文同行（`第一条　为加强……`），**不是标题层级**。
  → 渲染为仿宋三号正文，与条标式的楷体条标题**视觉不同**，这是正常的。
  → 因此章条式**篇幅更紧凑**（条号与正文同行，不独占行）。
- **章条式的条号全篇连续**，不按章重置（`第三十三条` 跨章继续递增）。这是"第X条"体例惯例。
- 章条式若把 `第一章` 写成 `一、`，`ART_RE` 不会触发（`ART_RE` 匹配的是"第X条"而非"第一章"），**不会重置编号**——但为可读性，章标题仍建议用 `第一章　xx` 明确形式。

### 转换脚本骨架

```python
import re, pathlib
CN = "〇一二三四五六七八九十"
def zh_num(n):
    if n <= 0: return str(n)
    if n <= 10: return CN[n]
    if n < 20: return "十" + CN[n-10]
    if n < 100:
        t, o = divmod(n, 10); return CN[t] + "十" + (CN[o] if o else "")
    return str(n)

CHAPTERS = {"总则", "采购方式", "组织与委托", "采购程序", "附则"}  # 白名单，防误判
CHAP_RE = re.compile(r"^([一二三四五六七八九十]+)、\s*(.+)$")
SUB_RE  = re.compile(r"^（([一二三四五六七八九十]+)）\s*(.*)$")

out, chap, art = [], 0, 0
for ln in pathlib.Path(SRC).read_text(encoding="utf-8").split("\n"):
    s = ln.strip()
    if not s: out.append(""); continue
    m = CHAP_RE.match(s)
    if m and m.group(2).strip() in CHAPTERS:      # ← 白名单判断，别用行号!
        chap += 1; out.append(f"第{zh_num(chap)}章　{m.group(2).strip()}"); continue
    m2 = SUB_RE.match(s)
    if m2:
        art += 1; body = m2.group(2)
        out.append(f"第{zh_num(art)}条　{body}" if body else f"第{zh_num(art)}条"); continue
    out.append(s)
```

**坑：不要用行号（如 `i > 3`）判断是否为章标题。** 首行/次行是公司名与办法名，靠行号跳过会漏掉第一章。用**章名白名单**判断。

**转换后必须核对**：章数、条数、首条/末条号连续无跳号。

## 篇幅校准（避免把正常版面当 bug）

`gb_gongwen.py` 用**三号字（16pt）+ 固定 30 磅行距 + A4 公文页边距**，每页约 **21 行 × 28 字 ≈ 588 字**。

参考基线（实测）：

| 字数 | 页数（条标式） |
|------|--------------|
| 5,600 字 | 约 16 页 |
| 6,700 字 | 约 18 页 |

**结论**：一份 6,000-7,000 字的制度排到 **15-18 页是正常的**，不是排版 bug。判断页数是否异常，应与用户既有同类制度**横向比对**（取其 docx 用 Word COM `ComputeStatistics(2)` 读页数），而不是凭"感觉太长"就返工。

误判信号：看到 18 页 → 以为行距/字号出错 → 改 md 结构 → 页数不变。**先量基线再动手。**
