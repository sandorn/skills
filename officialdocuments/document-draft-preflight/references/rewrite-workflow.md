# 制度重写工作流 — 以既有文本为母本重新撰写\n\n> 本工作流适用于**以一份既有制度（母本）为基线，重新撰写更规范/更全面版本**的场景。\n> 典型触发：用户说\"以XX文件为母本重新写\"、\"现在执行中的是A，请根据A重写B\"。\n>\n> 与起草前置（`SKILL.md` 场景 A）的区别：\n> - 场景 A：**无指定母本**，从零起草，问用户管理模式\n> - 本工作流：**有明确母本**，以母本为基线重构\n\n---\n\n## 一、先决条件确认（5分钟）\n\n### 1.1 定位母本与目标输出\n\n- [ ] 确认用户指定的母本路径（别猜），`read_file` 或 提取全文\n- [ ] 确认母本的**版本属性**：已发布执行中 / 在推稿 / 已废止\n- [ ] 确认目标输出的文件格式：docx（章条式脚本）/ md + Pandoc / 纯 md\n- [ ] 确认目标目录是否有**同主题在推稿件**（执行 `search_files` 检索），防止产出平行冲突\n\n### 1.2 用户管理背景确认\n\n即使有母本，仍应快速确认以下三点（写在代码注释或设计说明里）：\n\n| 事项 | 母本可能写 | 但实际可能不同 |\n|------|-----------|---------------|\n| 部门称谓 | \"招商租赁部\" | 实际用\"招商运营部\" |\n| 决策机构 | \"总经理办公会\" | 实际是\"办公会\"或用全称 |\n| 报批上级 | \"母公司审批\" | 部分事项可自决 |\n\n> 最好在用户说\"重新写\"时紧接着问一句，不要假设母本的组织称谓仍然适用。\n\n---\n\n## 二、结构化提取母本\n\n### 2.1 提取段落与表格顺序\n\n编写 `_extract.py`，用 python-docx 按 body 子元素顺序输出：\n\n```python\nfrom docx import Document\nfrom docx.oxml.ns import qn\n\nd = Document(母本路径)\nbody = d.element.body\nti = 0\nfor child in body.iterchildren():\n    if child.tag == qn('w:p'):\n        txt = ''.join(n.text or '' for n in child.iter(qn('w:t')))\n        if txt.strip(): print('[P]', txt.strip())\n    elif child.tag == qn('w:tbl'):\n        print(f'===== 表 {ti} =====')\n        for ri, row in enumerate(d.tables[ti].rows):\n            cells = [c.text.strip() for c in row.cells]\n            print(f'R{ri}:', ' | '.join(cells))\n        ti += 1\n```\n\n**为什么不用直接读 `d.paragraphs`？** 因为段落列表不包含表格——用 body 子元素遍历才能保持段落和表格的**版面顺序**，且能分辨表格嵌套在哪个段落之间。\n\n### 2.2 对比母本架构 vs 新稿预期架构\n\n| 维度 | 母本结构 | 新稿预期变化 | 处理方式 |\n|------|---------|-------------|----------|\n| 章数 | 3章 → 拟扩7章 | 增加审批分级/商务条款/流程/风控 | 逐章对照，**不随意删母本条**（某条被吸收到新章，附则须写废止对应关系） |\n| 条数 | 无编号→拟编号33条 | 母本全篇无条编号 | 按新章分配条编号，母本每个子句都应有对应项 |\n| 附件 | 1张价格表 | 保留价格表+新增4个附件 | 价格表数据**逐格照录**，不编辑、不化简 |\n| 折扣规则 | 3条备注混在价格表尾 | 拆入正文独立条款 | 计算基数、叠加规则、审批路径一一对应重建 |\n| 车位优惠 | 一行带过 | 独立章节+附件配置表 | **先检索是否有成文标准，无则写框架+待定附件** |\n\n### 2.3 母本关键数据校验\n\n- **价格表行数+总面积**（如 40 行 + 74,721.56㎡）必须与新稿一致\n- **折扣比例**（5%/10%/10%三条）语义是否清晰（母本备注存在歧义，如\"租赁1层-2层面积\"→实际是面积分档还是楼层分档）\n- **小数精度**（带千分号的保留，带小数位的保留，整数的保留）\n\n---\n\n## 三、重写主体\n\n### 3.1 正文设计原则\n\n1. **结构升级不加条数膨胀：** 母本3章无编号 → 新稿若扩为7章33条，应确保母本每个决策点（价格体系/有效租金/续租扩租/增值服务/保密/解释）均有对应，不遗漏。\n\n2. **折扣规则重构三注意：**\n   - 注意一：母本备注中的折扣计算基数是\"价格体系基础价\"还是\"已折扣后的价格\"？新稿必须统一\n   - 注意二：母本中的\"再下调不超过10%\"可能被不同的审批路径（二次下调 vs 突破审批）引用——拆解时要确保权限归属不错误平移\n   - 注意三：**折扣叠加后上限必须与体系调整上限闭环**，不产生权限倒挂\n\n3. **车位优惠的实证原则：**\n   - 停车场资料检索（搜索 `*车位*` `*停车*` `*租金计算*`）确认现行管理模式\n   - 如已整体外包→租户的\"车位优惠\"是**固定车位配置名额 + 免费临停时长**，不存在\"租面积送车位\"标准\n   - **不要凭空写数字**（如\"每100㎡免费送1个车位\"），只在附件中以**建议值带注释**形式呈现\n\n4. **审慎对待母本中没有的条款：** 新稿新增的履约保证金、退租结算、保密义务等条款，应在附则或设计说明中注明\"新增，母本无对应条款\"，让用户知道哪些内容是外来的。\n\n### 3.2 价格表重构\n\n- **表头不变**（分区/实际楼层/电梯楼层/建筑面积/表面租金/装修期/免租期/有效租金）\n- **行数不变**（含合计行、含同楼层多行如12层3行）\n- **数据逐格照录**，从结构化提取的输出直接 map 进新脚本\n- 备注区折扣规则从价格表移出至正文独立条款，价格表仅保留体系数据\n\n### 3.3 折扣规则清晰化手法（以2025第二版为例）\n\n母本模糊点：\"租赁1层（含）-2层（不含）面积的客户，可在上述租赁价格体系基础上下调最高不超过5%\"\n→ 模糊点1：是楼层数还是面积数？新稿改为\"承租面积相当于N个楼层建筑面积\"\n→ 模糊点2：\"再下调\"没有限额？新稿改为\"标准折扣成交价格基础上最高再下调不超过10%\"\n→ 模糊点3：叠加总封顶不清？新稿改为\"叠加后总比例不得超过X%，超过则升级\"\n\n同步更新附件审批清单，使清单与正文的双向引用不矛盾。\n\n---\n\n## 四、版式引擎选择与排版\n\n### 4.1 优先选择\n\n- **已有同系列章条式脚本的**：优先复用该脚本（复制为 v2 后修改）\n- **无同系列脚本的**：用 `gb_gongwen.py`（条标式）或新建 python-docx 脚本\n\n### 4.2 质检说明\n\n- `qa_docx.py` 对于**条标式**（gb_gongwen 产出）的检查精确到编号连续性。\n- 对于**章条式**（python-docx 直接排版）的产出，qa_docx 的页边距检测和命名样式检查可能因排版引擎差异而误报：\n  - 章条式脚本在 run 级指定字体（不在命名样式表），qa_docx 的样式检查报 N/A 属正常\n  - 章条式脚本用 python-docx 默认段落设置（非 gb_gongwen 的 XML 级设置），页边距 twips 值与 qa_docx 期望值可能有 ±2 twip 差异\n  - **处理方式**：如果脚本是既有经认可的，**不修改正确文档以适配检查器**；改用独立的程序化核验（见下一节）\n\n### 4.3 独立程序化核验（章条式脚本专用）\n\n编写 `_verify_clean.py` 覆盖五项：\n\n1. **页边距**（mm 显示，确认是否符合 GB/T 9704 标准）\n2. **抽样字体**（大标题/章标题/条标题/正文 的 run 级实际字体与字号）\n3. **条文完整性**（条数、章数、附件标题、表格数）\n4. **关键修改点逐条核验**（用一个 checks 字典：name→搜索关键词，对\"清零类\"取反）\n5. **Markdown/异常字符残留**（**/##/~~/]( / 锛/None/Traceback）\n\n代码结构参考：\n\n```python\nchecks = [\n    ('简称定义', '本办法所称总经理办公会'),\n    ('旧称清零', '招商部门'),  # 清零类取反\n    ('15%收口', '总折扣比例不得超过15%'),\n    ...\n]\nfor name, key in checks:\n    hit = key in full\n    if '清零' in name:\n        print(f\"{'✅' if not hit else '❌'} {name}\")\n    else:\n        print(f\"{'✅' if hit else '❌'} {name}\")\n```\n\n---\n\n## 五、最终交付\n\n### 5.1 产物清单\n\n| 产物 | 文件名 | 说明 |\n|------|--------|------|\n| 清洁版 docx | `北京中言XX办法（2026版）-清洁版.docx` | 正文+附件，可直接上会 |\n| 修订对照表 docx | `北京中言XX办法-修订对照表.docx` | 横向A4，条款/修订前/修订后/理由四列 |\n| 生成脚本 | `生成脚本_XX办法2026_v2.py` | 可复现（含价格表数据），存历史版本备份 |\n| 提取脚本 | `_extract_母本.py` | 临时脚本，用完清理 |\n| 核验脚本 | `_verify_clean.py` | 临时脚本，用完清理 |\n\n### 5.2 上会前3确认\n\n1. **母公司报批路径**——新稿中的母公司报批要求与旧版及现行授权清单是否一致\n2. **制式合同比对**——逾期天数/保证金/押付/违约处理与合同是否一致（如合同无法读取，写在交付说明中请用户人工校对）\n3. **停车位等附件待定值的衔接**——附件填列前的过渡管控是否与正文一致\n\n### 5.3 备份建议\n\n- 清洁版 docx 和修订对照表：备份至 `历史版本备份/` 目录，文件名加日期后缀\n- 生成脚本（v2）：同样备份至 `历史版本备份/`——docx 可能被 WPS/Word 重存后二进制不可 diff，有脚本才能追溯\n- 临时提取/核验脚本：清理\n
