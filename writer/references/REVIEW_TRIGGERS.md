# 审查触发体系

> 本项目**质量优先于速度**。正文修改后自动激发审查，不等待用户手动触发。

---

## 一、审查功能清单

| # | 审查 | 维度 | 耗时 | 触发方式 |
|---|------|------|------|---------|
| Q | quick | 纯规则扫描 | 30s | **自动** — 写章自检 |
| D | daily | 8维 | 3min | **自动** — 每章写后 |
| S | solo | 15维 | 5min | **自动** — 每5章 |
| L | lean | 27维 | 10min | **自动** — 每10章 |
| F | full | 43维(4Agent) | 30min | **自动** — 每卷/批量>20章 |
| M | manual-pass | 语调+文风+禁令 | 不限 | **人工** — 用户要求逐章通读 |
| T | targeted-audit | 用户指定 | 不定 | **人工** — 用户指定维度 |
| C | setting-consistency | 设定跨文件 | 5min | **人工** — 设定变更后 |
| O | master-outline-audit | 总纲暗线 | 5min | **人工** — 大纲规划完成后 |
| LQ | longform-quality | 趋势分析 | 10min | **自动** — 每100章 |

---

## 二、自动激发规则

> **审查层级嵌套**：quick ⊂ daily ⊂ solo ⊂ lean ⊂ full。采用**替代升级**——只运行当前适用的最高层级，不叠加。

### 每章写后 (write Step 4)
```
触发: daily(8维) — 包含 quick 自检
条件: 无条件，每章必跑
```

### 每5章
```
触发: solo(15维) — 替代 daily（包含 daily 全部 8 维）
条件: chapters_done % 5 == 0
```

### 每10章
```
触发: lean(27维) — 替代 solo
条件: chapters_done % 10 == 0
```

### 每卷/批量>20章
```
触发: full(43维, 4Agent) + review-cycle(5步) — 替代 lean
条件: 写完一卷或批量写章 >20章
```

### 每100章
```
触发: full + longform-quality-monitor — longform 独立于审查层级，叠加运行
条件: chapters_done % 100 == 0
原因: longform 检测的是跨章趋势（声音漂移/情绪单调/风格指纹），与 full 的横切面检查是正交维度
```

### 润色后 (manual-polish / style-transfer)
```
触发: daily(8维) — 最低审查
条件: 润色完成后
原因: 润色可能引入新问题（字数震荡/AI腔/污染）
```

### 修复后 (post-review-fix)
```
触发: quick + daily
条件: 修复管线完成后
原因: 验证修复未引入新问题
```

### 设定文件变更后
```
触发: setting-consistency-audit (人工确认后执行)
条件: setting/ 下任何 .md 被修改
```

## 三、仅人工触发

以下审查**永远不会自动运行**，必须用户明确说出对应触发词：

| 审查 | 用户说什么 | 人工触发原因 |
|------|----------|------------|
| **manual-pass** | `逐章检查` `不用脚本` `一章一章过` | 主会话逐章通读，允许只读脚本，每会话≤5章，进度文件防中断 |
| **targeted-audit** | `定向审查` `专项审查` | 用户指定审查维度，系统无法预判关注点 |
| **setting-consistency-audit** | `设定审查` `交叉审查` | 跨文件对比需要用户确认修改意图 |
| **master-outline-audit** | `暗线审查` `总纲对齐` `大纲一致性` `大纲有没有问题` `总纲和卷纲对得上吗` `暗线都落地了吗` `各卷大纲有没有矛盾` | 多卷大纲完成后一次性检查 |

---

## 四、质量闸门

任何自动审查命中 **blocking 问题** 时：
1. 立即停止后续操作
2. 报告 blocking 清单
3. 等待修复后重跑审查
4. 全部通过才允许继续

```
写章 → quick(通过) → daily(通过) → 可继续
                ↓ 不通过
              修复 → 重跑 → 通过 → 继续
```
