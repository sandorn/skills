# 角色状态追踪更新

> **适用范围**：写完一卷(≥60章)或批量写章(>10章)后更新角色状态追踪文件。**不适用**：单章日更——单章的状态变化在写章管线中自动记录到 memory-novel MCP 知识图谱。
> **加载时机**：审查循环 Step 4（追踪更新）或卷末批量写章后。**非日常操作**。

---

## 触发条件

- 写完一卷（如60章）后
- 用户明确要求"更新角色状态"
- 审查循环 Step 4 的追踪更新环节

---

## 全量更新流程（卷末必做）

### 1. 读卷末章 + 前一卷末章

卷末章包含大量总结性信息（主角翻笔记本备注所有角色），是最高密度信息源。

```
卷末章通常 = ch60, ch120, ch180, ch240, ch300...
前一卷末章 = 用于对比变化
```

### 2. 读每个主要角色"最后出现"的章节

角色最后一次出场通常包含其最终状态。按以下优先级找：

| 优先级 | 方法 | 示例 |
|--------|------|------|
| 高 | 卷末章内的备注/总结段落 | ch297 主角翻笔记本逐一备注所有角色 |
| 高 | 角色名字出现在章标题 | ch288-重要角色章节, ch282-配角抉择 |
| 中 | grep/pattern search 按文件名模式缩小范围 | `grep -l '角色A' chapters/ch2[5-9]*.md` |
| 低 | 全量搜索（大规模时降级使用） | `grep -r '角色B' chapters/` |

### 3. 批量搜索技巧

用文件名模式 glob 缩小搜索范围，避免扫描全部章节：

```bash
# 搜索角色在后期章节的出现
grep -l '角色A' chapters/ch2[5-9]*.md

# 多个角色可合并搜索
grep -lE '角色A|角色B|角色C' chapters/ch29*.md
```

### 4. 合成状态文件

模板格式：


### 5. 输出文件

- 旧项目中文目录：`追踪/角色状态.md`
- Writer 新目录：`tracking/current_state.md`

## 增量更新（批量写章后）

写5-15章批量的情况，不需要全量重读。只扫描新章：

```bash
# 扫描新章中出现的已知角色名（替换为项目实际角色名）
grep -lE '主角|女主|配角A|配角B|配角C' chapters/ch29[0-5]*.md
```

发现状态变化后，逐条更新 `追踪/角色状态.md` 对应角色的行。

---

## 常见陷阱

- **不要只看卷末章就结束**。卷末章虽然有总结段落，但角色最后的功能性出场可能在更早的章节（如 ch282 配角A拒绝转会，而 ch297 只写了简短备注）
- **注意角色"缺席"**。如果一个角色在多章内未出现，应标注"已超X章未出场"
- **已去世角色单独标注**。不应简单删除——需注明去世章节和原因
- **新旧角色不要遗漏**。新卷可能引入新角色，需要在追踪文件中新增条目
