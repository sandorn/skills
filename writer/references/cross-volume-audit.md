# 跨卷连续性审查规程

卷间审查（如完成第 N 卷后审查第 N+1 卷）必须额外执行本规程，因为 43 维审计的批量审查流程仅作用于单卷内部，无法发现卷间断裂。

## 触发条件

满足任一即必须执行：
- 新卷首章阅读中发现场景/时间/地点与前卷结尾不接续
- 角色修为/装备/状态与前卷记录不符
- 前卷审查报告中有「跨卷伏笔待回收」的标注
- 当前卷章节数 ≥20 章（累积偏差风险增高）

## 步骤

### Step 1: 卷间时间线接续检查

1. 读前卷最后 3 章的结尾段落（检查锚点状态）
2. 读当前卷开头 3 章的起始段落（检查衔接起点）
3. 比对：
   - 场景是否一致？（前卷在丹塔，本卷在荒野 → 需过渡标记）
   - 时间是否连续？（「三日后」「一个月后」等标记是否缺失）
   - 角色状态是否一致？（前卷重伤 → 本卷生龙活虎需疗伤过程）

**典型问题与修复：**

| 问题 | 修复方案 |
|------|---------|
| 场景不接续 | 加1-2句过渡：「从丹塔传送阵出来已是三日后。返回战场取回物资时——」 |
| 无时间标记 | 加「{N}日后」或「与此同时」等时间提示 |
| 角色状态断裂 | 在首段补充状态变化的原因 |

### Step 2: 角色修为/状态一致性检查

1. 从 `state-files/characters.json` 读前卷末的角色修为数据
2. 用 Python 扫描当前卷各章，抽取角色修为/等级的关键词
3. 比对：林尘修为是否延续？配角修为是否延续？

### Step 2B: 术语/命名体系一致性检查（新增）

跨卷设置名称漂移是长篇中最隐蔽也最致命的断裂。不同卷之间对同一角色的称呼必须一致。

**检查方法：**
1. 从 vol1 的 state-files 或第一卷正文中提取关键命名锚点（势力名、人物称号、地名）
2. 用 `search_files` 扫描当前卷各章，比对命名是否一致
3. 关注：五帝/七宗/三殿类体系名称、人物尊称（仙帝/大帝/尊者）、地名（天元城/中天帝朝/九天灵域）

**典型问题：** 卷4建五帝体系为「天元仙帝/玄冥仙帝/苍炎仙帝/白帝/轮回仙帝」，但卷5出现了「苍龙帝/九苍玄女/秦无锋/黄帝」等多套不兼容命名 → 各章各自使用不同的命名体系，互不匹配。

**修复策略（novel-pipeline 2.2E）：**
- **命名漂移是单处偏差？** → 策略A：统一替换该卷中所有漂移处，映射回标准名
- **整卷用了不同的体系？** → 需确认是否作者有意更换。若是，在卷首加过渡注释

**实操：「以第N章为标准」的统一流程**
当多章使用互不兼容的命名体系（如五帝名在不同章用3-5套不同名称）时：

1. **选标准章**：找最早出现的或命名最集中的一章作为标准（通常选关键剧情章，如 ch197 首次出现五帝残影对质）
2. **提取标准命名表**：从该章 grep 出所有该体系名称及出现频次
3. **逐章 diff**：对其他各章，扫描是否有标准表外的名称
4. **建立映射**：将非标准名映射到标准名（可能需按方位/属性/剧情角色判断对应关系）
5. **逐章替换**：
   - 先替换长名（全名+限定词）→ 再替换短名（单字名）
   - 替换后检查「双重名」残留（如 玄冥仙帝仙帝→玄冥仙帝）
6. **验证**：用 `search_files` 确认无旧名残留

**映射原则示例（五帝体系）：**
| 方位 | 标准名 | 常见漂移名 |
|------|--------|-----------|
| 东域 | 天元仙帝 | 苍龙帝/青龙帝/青帝 |
| 南域 | 苍炎仙帝 | 炎帝/赤帝/焰帝 |
| 西域 | 白帝 | 金帝/金锋 |
| 北域 | 玄冥仙帝 | 玄帝 |
| 中域 | 轮回仙帝 | 黄帝/后土/秦无锋/九天玄女 |

### Step 2C: 版本残留检测（新增）

当某章的林尘修为与前后章/前卷末相差两个大境界以上时，极可能是**生成时的旧版残留**。

**检测方法：**
1. 取当前卷末状态文件中的林尘修为
2. 对卷中每一章，扫描该章内的修为/战力关键词
3. 若某章的修为关键词比实际修为低了两个以上大境界（如练气 vs 金丹/人仙），标记为**版本残留触发点**
4. 对触发点做全文扫描，确认涉及修为/战力/装备描述的段落全部需要升级

**典型问题：** ch197 出现 6 处「练气八层」→ 该章使用了旧版设定檔的修为基准，林尘实际应为人仙后期。

**修复流程（绝不使用全局正则替换！）：**
1. 读全文，定位所有旧版修为关键词
2. 逐处替换为当前卷实际修为
3. 检查替换后的战力描写是否合理（练气级招数升级到人仙级后是否需要补充描写）

### Step 3: 伏笔跨卷追踪

1. 从 `state-files/foreshadowing.json` 读取 active 伏笔列表
2. 对每条 `status: "unresolved"` 的伏笔：
   - 用 `search_files` 在全卷搜索伏笔关键词
   - 记录该伏笔"连续未出现的卷数"
   - 连续 ≥2 卷未出现 → ⚠️ S3 警告
   - 连续 ≥3 卷未出现 → ⚠️ S2 建议
   - 连续 ≥4 卷未出现 → ⛔ S1 阻塞

**关键词示例：** 碎月印记→`碎月`+`三瓣弯月`；血渊组织→`血渊`+`灵根种子`；段长老→`段长老`

### Step 4: 断裂伏笔修复策略

发现断裂伏笔后：
- **有自然插入点**: 在当前卷插入回调场景（旁观者法/回想法/对话法/战利品法）
- **无自然插入点**: 在下一卷开头安排回收，更新 foreshadowing.json 的 payoff_window

回调场景插入技巧：人群加神秘观察者、角色心理活动提及、角色对话带回线索、从敌人身上搜出伏笔物品

### Step 5: 归档

修复完成后更新 `state-files/foreshadowing.json`：新增回调标记为新伏笔、已回收移至 resolved。运行 `archive_state.py` 同步 memory-novel。
