# 批量跨设定交叉校验（Batch Cross-Validation）

> **相关文件**：[`setting-consistency-audit.md`](setting-consistency-audit.md) — 设定文件内部的跨文件一致性审计（5 步流程），适用于设定文件写完/大幅修改后。
>
> 本文件专注于**批量审查中的正文 vs 设定交叉校验**（≥5 章场景）。

批量审查（≥5章）时，最易遗漏的错误是**正文与多份设定文档之间的数值/状态不一致**——单章审查很难发现，因为偏差是累积的。

---

## 执行流程

### Step 1：提取设定基准值（Build Reference Table）

审查开始前，**先通读所有设定文档**并提取可量化的约束值：

| 设定来源 | 提取内容 | 示例 |
|---------|---------|------|
| 数值体系.md | 各阶段属性/等级/价格/利润 | ch41-50: 攻15防15魔8 |
| 系统设定.md | 权限等级/金币消耗/每日额度 | L4: 单属性≤25点，18次/天 |
| 角色卡.md | 性格边界/行为底线/禁止行为 | "绝不向任何人透露金手指" |
| 反派设计.md | 各反派出场时段/冲突层级 | 马彪：前期（ch11-55） |
| 写作规范.md | 禁令清单/质检阈值 | 每章≥2500字，无—— |

### Step 2：逐章过检（Chapter-by-Chapter Scan）

对每章正文，对照基准值检查：

```
FOR each chapter:
  FOR each setting constraint:
    IF value_in_text ≠ value_in_setting:
      → 记录偏差（位置 / 正文值 / 设定值 / 差值）
    IF event not_in timeline:
      → 检查是否越界（反派提前出场/剧情跳跃）
```

### Step 3：输出交叉校验表

将结果汇总为 S1-S4 分级报告，格式：

```markdown
| # | 问题 | 章节 | 正文值 | 设定值 | 级别 |
|---|------|------|--------|--------|------|
| 1 | 属性数值偏差 | ch44 | 攻10防10 | 攻15防15 | S1 |
```

## 经典案例

### 案例1：属性数值滚雪球

> **场景**：数值体系规定 ch41-50 阶段属性为攻15/防15，但正文从 ch31-40 的攻10/防10 延续下来，到 ch60 才涨到防13/攻13。
>
> **根因**：单章审查时每章偏差只有1-2点，不触发 warning；累积到卷末才发现差了30%-50%。
>
> **修复策略**：在 ch44（激活属性战斗）或 ch47（行会战前）加入1-2句属性升级提示，将数值逐步推至设定值。

### 案例2：权限等级与系统设定错位

> **场景**：主角28级，正文标注为 L2（入门），但系统设定规定 21-30级 = L3（熟练）。L3 已在前面章节正确使用，此章突然回退到 L2。
>
> **根因**：写章时参考了错误版本的设定文件，或写作期间权限表被口头协商修改但未落盘。
>
> **检测方法**：对每章正文中出现的"权限等级：Lx"标注，横比系统设定权限表（L0-L6 对应等级区间）。不一致即 S1。
>
> **修复策略**：统一以系统设定文件为权威来源，修正正文中所有权限标注。

### 案例3：同一事件重复写入（属性带入写了两次）

> **场景**：ch13（25级，L3，攻+3防+3）和 ch14（28级，L2，攻+2防+2）都写了"热流从脊椎窜上来→巷子里试拳"的桥段，描述高度相似但数值不一致。
>
> **根因**：批量写章时单章独立生成，没有跨章去重检查。此问题只有批量审查才能发现。
>
> **检测方法**：对相邻章节搜索共同关键词（如"属性同步""热流""巷子里挥拳"），检查是否重复描述同一事件。
>
> **修复策略**：保留与系统设定一致的一版，另一章删除或改写为其他内容。

### 案例4：时间线崩溃（年代考据错误）

> **场景**：2001年热血传奇开服仅10天，正文出现"37级战士""入会三个月""30万金币"。以传奇当年的升级速度，第一个37级玩家至少在一个月后出现，行会系统开服初期也不存在。
>
> **根因**：作者用后续版本的记忆写早期时间线，或对2001年传奇的升级曲线无准确认知。
>
> **检测方法**：对正文中的等级/金币/行会时间标签，核实是否符合年代背景。2001年传奇关键数据点：开服第一周最高等级约22-25级；30级约需3-4周；37级约需6-8周；行会系统开服首月基本不存在。
>
> **修复策略**：将等级和金币量下调至符合年代实际的数值，删除"入会三个月"等时间锚点。

### 案例5：章节等级倒退（数值回跳）

> **场景**：ch22 末尾主角已升至31级，ch31 已是32级；但 ch34 描写主角从"差半格到三十级"→30→31级的冲级过程，仿佛之前的升级从未发生。整章在时间线上无法与前后衔接。
>
> **根因**：该章是为填补早期时间段的"补写章"，但在章节排序时被错误放置在后期章节之后，导致主角等级出现"倒退-重升"的循环。
>
> **检测方法**：对每章提取主角等级/属性/金币余额，列出全卷数值时间线（ch→level→gold→attr），检查是否有非闪回的数值回退。任何无合理解释的等级/数值下降都是 S1。
>
> **修复策略**：**补写章等级上移法**——不删章，而是将该章的等级区间整体向上平移，使起点≥前章终点。操作要点：(1) 读取前章结尾等级作为起点；(2) 将冲级目标改为下一个技能/装备节点；(3) 调整章节内所有等级/经验/金币数字以匹配新区间；(4) 同步修改结尾对话中的等级数字（如钱大富的\"从X到Y才几天\"）。案例：ch34原29→30→31学魔法盾，修正为32→33→35冲地狱雷光，保留刷怪/攒金币叙事骨架，只替换技能目标和数字。

### 案例7：文本污染——跨章节粘贴错误

> **场景**：ch54（2001年11月，赵天龙会面）文末出现"孙经理""深蓝资本""季东海的名片"等内容，与本章赵天龙场景完全无关。经核对，这些内容属于 ch111+（深蓝资本首次接触）的文本，被误粘贴到 ch54 末尾。
>
> **根因**：写作时在文本编辑器间切换，选择→复制→粘贴操作失误，导致远章段文本混入前章终点。
>
> **检测方法**：逐章检查章末 5 行是否有与本章场景无关的专有名词（人名、公司名、地名）或时间锚点（如"2003年"出现在2001年章节）。特征信号：章末出现章节中从未出场的人物名或机构名。
>
> **修复策略**：直接删除污染行。判断标准：该内容中的专有名词是否在前后 5 章中出现过？如果没有 → 污染文本，删除。

### 案例8：L3/L4权限跨章不一致（权限级别回退）

> **场景**：ch64（2002年1月，40级）正文标注"L4权限已经稳定运行了一个多月"，但 ch74（2002年4月底，仍为40级）却写"L3权限的事情一旦被人知道"。同是 L4 阶段的章节，权限标注出现 L3→L4→L3 的陀螺式回退。
>
> **根因**：批量写章时间跨度大，作者在中途可能参考了旧版笔记或记忆偏差，将已升级的权限写回了前一档。单章审查（如 ch74 独立看）不易触发警报，但批量交叉校验会暴露。
>
> **检测方法**：对全卷提取权限标注（"Lx权限"），按时间线排列，检查是否有降级。任何 L4→L3 的回退都是 S1。
>
> **修复策略**：统一以系统设定权限表（L4=31-40级）为权威来源，将晚期章节的 L3 全部修正为 L4。

### 案例9：感情线双重确认——同一里程碑写了两遍（情感回跳）

> **场景**：ch108（3月，河边）女主已说出\"我也是\"级别的告白，关系实质上已确认；但 ch116（6月，云海楼）又写男主\"今天起你就是我女朋友\"，仿佛之前的确认从未发生。两章各自独立阅读时情感强度都足够，但放在一起构成重复确认——读者会感到角色记忆断裂。
>
> **根因**：作者在不同时间写这两章时，可能忘记前文已达到的关系阶段，导致每个场景都按\"首次确认\"来写。单章审查看不出问题，只有批量审查时才会发现同一个关系里程碑出现了两次。
>
> **检测方法**：对涉及感情线的章节，提取每次关系推进的关键节点（认识→接近→试探→确认→亲密），建立关系时间线。任何\"降级后重新升级\"都是 S1。关键词搜索：\"女朋友\"/\"男朋友\"/\"在一起\"/\"确定关系\"等宣告性用语——这些词在同一感情线里只应出现一次。
>
> **修复策略**：**分镜式情感双确认**——不删任何一章的场景，而是让后发的确认成为\"等来的确认\"，在前章加上等待的伏笔、在后章加上回顾的独白。具体操作：(1) 在后章确认场景末尾加入先发方的内心独白，点明\"其实X月就想说了，但等你先说\"；(2) 将时间跨度写进独白（\"从X月等到X月\"），将重复确认转化为\"我先说/你后说\"的互文结构；(3) 保留两章各自的情感力度，让等待期成为情感叙事的一部分而非bug。

### 案例10：加盟/势力/店铺数量跨章回退（数值漂移）

> **场景**：ch313正文写到加盟店114家，但ch341突然回退到103家，ch344又到107家。中间无任何加盟店退出的叙事交代。
>
> **根因**：批量写章时作者在不同时间写的章可能参考了不同版本的数字笔记，或"103"是笔误（应为"113"）。此问题只有逐章提取关键数字并排列时间线才能发现。
>
> **检测方法**：对全卷提取所有涉及"数量"的断言（加盟店数/金币余额/等级/覆盖省份等），按章节排列为时间序列。任何非叙事驱动的数字回退（如无"关闭门店"情节却数字下降）都是 S1。
>
> **修复策略**：以最新且最明确的事件章节（如明确写了"第100家在哈尔滨开业"的ch305）为锚点，逐章向前/向后推导正确数字，将回退章节的数字修正为合理值。若回退数字涉及后续叙事（如"一百零三家"被用作安静区SOP的推进节点），需确保修正后的数字与后续叙事一致。

## 关键检查项清单

批量审查时至少覆盖以下交叉校验：

- [ ] **属性/等级** vs 数值体系各阶段基准
- [ ] **权限等级** vs 系统设定权限表（L0-L6对应章节；检查降级回退）
- [ ] **金币余额/消耗** vs 系统设定消耗表（技能解锁费/激活费是否扣对）
- [ ] **反派出场时段** vs 反派设计层级表
- [ ] **感情线占比/推进** vs 女主卡约束 + 关系里程碑时间线（同一宣告性用语仅出现一次）
- [ ] **时间线** vs 大纲节拍表时间跨度
- [ ] **伏笔推进** vs 追踪/伏笔清单
- [ ] **硬性禁令** vs 写作规范禁令清单
- [ ] **文本污染**：章末5行是否有不相关专有名词（人名/公司名）或错位时间锚点

---

## 注意事项

1. **数值体系是"已同步上限"而非"战斗中实际激活值"**：正文中主角可能只激活部分属性，但累积同步值不应长期停滞。
2. **权限升级应有触发文本**：系统设定要求"恰好达到阈值等级时自动触发"——正文中应有对应的系统提示。
3. **年代考据**：2001年的物价、技术（拨号上网/寻呼机/现金交易）应与世界观设定一致。
4. **同源复制规则**：游戏物品带出后游戏内保留——文中应有至少一处解释，避免读者困惑。
