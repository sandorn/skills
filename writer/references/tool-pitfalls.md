# 工具交互陷阱

> **适用范围**：AI 辅助写作环境中写章/审查时的工具交互注意事项。**不适用**：正常的写作/审查流程——本文件是补充性参考，不是必须遵循的管线步骤。
> **加载时机**：遇到工具报错/非预期行为时查阅。**非核心管线组件**。

---

## 陷阱一：文件读写污染（高破坏性）

**触发条件**：使用文件读取工具读取文件后，将返回的内容直接传给文件写入工具覆写同一文件。

**原因**：部分环境的文件读取 API 返回的内容可能包含行号前缀（格式为 `"1|内容\n2|内容\n..."`）或其他元数据标记。写入工具会原样写入，导致文件内容被元数据前缀污染。

**表现**：文件字数骤降数百字（因为中文内容被 `N|` 等 ASCII 前缀替换），再次读取时正常但统计字数异常。

**正确做法**：
- 读取和写入使用不同的路径/方式，不要在同一个回环中「读→不改→写」
- 如需修改文件，使用专门的文本替换工具（而非覆写整个文件）
- 读到的内容仅用于分析/参考，不直接回写

**修复已污染文件**：
```bash
sed -i 's/^[0-9]*|//' 被污染文件.md
```

## 陷阱二：Shell 中文编码转义

**触发条件**：在命令行中用 `echo` 追加中文内容到文件。

**原因**：shell 对含中文的长字符串可能触发转义错误，尤其是包含引号、括号等内容时。

**表现**：`unexpected EOF while looking for matching` 错误。

**正确做法**：
```
# ❌ 错误
echo "中文内容含"引号"..." >> file.md

# ✅ 正确
使用 Python 脚本 write/append 追加
或以单引号包裹，避免 shell 解析引号
```

---

## 陷阱三：子代理批次大小上限

**阈值**：每批 5-10 章为宜。超过上限会触发迭代预算耗尽或超时。

**原因**：子代理每章需要读取→写入→审计→修复的循环，章节数越多越早触及预算上限。

**策略**：
- 批量写章：每批 ≤5 章（写章每章消耗大量迭代）
- 批量审查：每批 ≤40 章（审查比写章省迭代预算）
- 委托返回后必须立即跑质检（禁令+字数），不信任自我报告

> **权威定义**：`references/hard-bans.md` B09 为批次上限的单一事实来源。

## 陷阱四：文本替换工具的转义漂移

**触发条件**：在文本替换工具（patch/find-and-replace）的匹配字符串中包含引号时。

**原因**：替换工具的序列化层可能对引号做额外转义，导致匹配字符串无法匹配文件原文。

**表现**：`Escape-drift detected` 或 `Could not find a match` 错误。

**正确做法**：
- 在匹配字符串中使用宽泛上下文定位，避免依赖引号精确匹配
- 如匹配包含引号的文本失败，改用命令行 `sed` 替换
- 或用 Python 脚本直接处理文件

## 陷阱五：echo 追加段落污染（高破坏性）

**触发条件**：用 `echo "长文本" >> chXX.md` 追加字数时，整段文本被当作单行写入（不带换行符）。

**原因**：shell 的 `echo` 在不同平台对换行符的处理不一致。追加的白描文本即使语义上有多个句子，文件系统中仍是一行。

**表现**：`split_paragraphs.py` 扫描出数千行超长段落（>42 汉字），全部来自最近追加的章节。实际遭遇：5716 行超长段落，80% 由 `echo >>` 追加污染产生。

**正确做法**：
1. **永远不要在追加字数的步骤后跳过段落拆分**：`echo >>` 追加字数后**立即**跑 `split_paragraphs.py`
2. 优先用 Python 脚本多行追加，而非 `echo >>`
3. 如必须用 `echo`，每句一行，手动插入换行

```bash
# ❌ 错误
echo "他穿过走廊。灯光昏暗。走廊尽头是一个房间。" >> ch040.md
# → 整个追加为一整行，超 60 字

# ✅ 正确：分行追加
printf "他穿过走廊。\n灯光昏暗。\n走廊尽头是一个房间。\n" >> ch040.md
```

**修复已污染**：
```bash
python scripts/split_paragraphs.py --batch chapters/ --max-len 60
```

## 陷阱六：文件写入工具的引号转义残留（中破坏性）

**触发条件**：通过文件写入工具写入含中文双引号 `"..."` 的内容时。

**原因**：文件写入工具在序列化内容参数时，JSON 序列化器将 `"` 转义为 `\"`。如果工具在写入磁盘前未将 `\"` 还原为 `"`，文件中会出现 `\"走了。路通了。\"` 这样的转义残留。

**表现**：大量章节中出现 `\"` 替代中文引号，集中在委托代理批量写章时出现（对话密度高的章更高发）。

**自动修复**：
```bash
# 扫描并修复所有转义引号
grep -l '\\"' chapters/ch*.md | while read f; do
    python3 -c "import sys;c=open(sys.argv[1]).read();open(sys.argv[1],'w').write(c.replace('\\\\\"','\"'))" "$f"
done
```

**预防**：
- `audit.py --fix-escaped` 内置转义引号检测+自动修复
- `audit.py --fix-escaped` 写入后自动扫描并清除转义引号
- 质检流水线步骤7专门扫描此类残留
- **全文统一用「」替代 `""`**，从根源避免转义问题

## 安全操作清单

以下操作在任何 AI 写作环境中都是安全的：

- `sed -i 's/——/，/g'` — 批量清除破折号（安全，不涉及编码问题）
- 代码执行环境中的 Python `open/write` — 完全可控
- 文本替换工具的短文本精确匹配（不含引号）— 可靠
- `python scripts/split_paragraphs.py --batch` — 段落拆分，独立工具
