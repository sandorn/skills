# 设定一致性跨文件审计（统一入口）

> **v7.0**：合并了 `cross-validation.md`（正文 vs 设定）和 `cross-setting-consistency.md`（大纲/设定/卷纲）的内容，成为一致性审查的**单一入口**。
>
> **覆盖范围**：设定文件内部一致性 → 大纲与设定交叉 → 正文与设定交叉校验 → 卷间衔接 → 正文修复后扫描。

## 何时使用

- 全书设定文件写完（或大幅修改后），与正文交叉审查一致性
- 发现正文中某个设定与设定文件描述不同时
- 每卷写完后，检查设定文件是否需要更新（角色状态、地点、系统推进）

## 审计流程（5步）

### Step 1：逐文件读取

读取所有设定文件，提取**可验证的硬断言**（数字、名字、时间、地点、规则）。跳过纯描述性内容。

示例：
```
世界观.md: 「主角家乡：宁市」「等级上限：50级」「2001年9月开服」
主角卡.md: 「出生1983年」「重生前46岁(2029年)」「父亲刘建国」「母亲王秀兰」
系统设定.md: 「L0初始：小红药×1」「L1：1-10级，5次/天」
数值体系.md: 「小红药100金币→100-150元」「裁决50万金币→1万-1.5万元」
女主卡.md: 「出生1984年」「2001年17岁」「父林海涛」
```

### Step 2：交叉表对照

将相同主题的断言放在同一行，标记一致/矛盾：

| 断言 | 世界观 | 系统设定 | 主角卡 | 数值体系 | 正文(ch01) |
|------|--------|---------|--------|---------|-----------|
| 主角年龄 | 18岁(2001) | — | 1983→18岁 | — | 「十八岁」 |
| 重生时间 | 「2001年9月」 | — | 「9月28日」 | — | 「9月28日」 |
| 系统来源 | — | — | — | — | ch451: 39号实验室 |

### Step 3：严重度分级

| 级别 | 定义 | 示例 |
|------|------|------|
| 🔴 S1 阻塞 | 设定文件之间/与正文**原则性矛盾** | 世界观说「来源不需要解释」vs 正文有39号实验室完整解释 |
| 🟡 S2 内部矛盾 | 两个设定文件**数值/规则不一致** | 系统设定L1可同步属性 vs 数值体系说ch01-ch10未同步 |
| 🟢 S3 缺失 | 设定文件缺漏，不影响叙事但影响完整性 | 世界观只写宁市，未收录省城/冰城/北京等后期地点 |
| 🟠 S4 潜在风险 | 描述略有出入但可解释，或未来可能演变为S2 | 记录为TODO，不阻塞写作 | 100级里程碑选项数在表格写5选3但章纲实际用6选3 |

## 多卷章纲交叉校验（Step 1.5 · v7.1 新增）

当项目有3卷以上章纲时，设定一致性审计必须扩展为**三层校验**：

### 层1：设定文件内部一致性
- story_bible.md ↔ characters.md ↔ power_system.md ↔ factions.md
- 检查：角色年龄、能力数值、触发条件、势力关系

### 层2：设定 ↔ 大纲交叉一致性
- story_bible.md ↔ master_outline.md
- power_system.md ↔ 各卷具现节点设计
- characters.md ↔ 各卷新增角色初登场章节

### 层3：卷间衔接一致性
- volume_N_chapter_outline ↔ volume_N+1_chapter_outline
- 检查：卷末等级 ↔ 下卷起始等级、卷末资产 ↔ 下卷初始资产、卷末钩子 ↔ 下卷首章

### 多卷校验清单

| 检查项 | 来源A | 来源B | 预期 |
|--------|-------|-------|------|
| 主角等级 | 卷末章纲 | 下卷卷首章纲 | 连续无跳跃 |
| 属性值 | power_system.md 表格 | 各卷具现节点选择 | 累计值一致 |
| 资产清单 | 上卷关键数据 | 下卷初始状态 | 继承无误 |
| 角色认知 | characters.md | 各卷角色发展追踪 | 认知边界逐步深化 |
| 势力状态 | factions.md 阶段演化 | 各卷章节事件 | 时间线对齐 |
| 具现节点 | power_system.md 表格 | 各卷具现节点设计 | 等级/选项数/颜色一致 |
| 伏笔回收 | tracking/hooks.md | 各卷章节 | 已埋伏笔有预期回收章 |

## 大型报告输出策略（v7.1 新增）

审查报告可能超过 ~8K tokens（多卷×4设定×多角色），**不要尝试单次 write_file 输出**。

**正确做法**：
1. 报告直接以文本形式输出（不写文件），除非用户明确要求保存到文件
2. 如果必须写文件，拆分为多个文件：概要+各严重度分级详情
3. 每个文件控制在 ~4K tokens 以内

## 常见陷阱（续）

### 5. 属性叠加计算陷阱

多卷项目中，主角属性是**累加**的。检查时必须手动计算累计值，不能只看单卷选择。

**错误做法**：只看60级选择了15%体质就认为体质=15%
**正确做法**：20级(10%) + 60级(15%) + 90级(20%) = 45%，与power_system.md表格核对

### 6. 角色认知边界跨卷演化

角色的认知边界随卷次逐步深化。characters.md中写的"第二卷不会怀疑"只是起点，不是终点。

**检查方法**：对每个角色，遍历其在各卷的出场章节，确认认知边界描述与实际剧情一致。

### 7. 里程碑节点选项数变化

100级里程碑+1选项是特殊规则。检查时必须确认：
- 100级之前：5选3
- 100级及之后：6选3
- 红卡正式开放(170级)：7选3（额外+1）
- 满级(200级)：7选3（额外+1红卡选项）

**常见错误**：在power_system.md表格中未体现里程碑变化，导致与章纲不符。

### 8. 具现节点章节编号与卷内小节号不一致

各卷的"具现节点设计"小节中的章节范围（如"第240~250章"）必须与正文实际章节号对齐。

**检查方法**：用grep搜索各卷章纲中的"第XXX章"，与"具现节点设计"中的章节范围交叉验证。

### 9. 容量/尺寸类资产前后矛盾

空间戒指、安全屋面积等资产在不同文件中可能有不同数值。

**检查方法**：搜索所有涉及"立方米"/"平米"/"容量"的断言，交叉验证。

### Step 4：正文抽样验证

对每个断言，抽样3-5章验证正文是否一致：

```
搜索: grep -l "宁市" 正文/ch*.md | wc -l  →  263/480章
搜索: grep -l "刘建国" 正文/ch*.md | wc -l  →  47章
搜索: grep "林海涛" 正文/ch*.md | wc -l     →  检查正文是否使用父名
```

### Step 5：修复优先级

1. 🔴 先修（阻塞叙事因果链的）
2. 🟡 后修（数值/规则矛盾）
3. 🟢 可放缓（补充性缺失）

## 常见陷阱

### 1. 设定文件是正文的「影子」

设定文件不是独立的——正文怎么写，设定就要怎么描述。**永远以正文为准**。如果正文与设定冲突，优先改设定文件。

### 2. 临终状态是全书情绪锚点

主角的临终动机直接关联开篇情绪张力。主角卡和ch01的临终描述必须一字不差地对齐。这不是「建议」，是硬性要求。

### 3. 系统来源必须收敛

如果正文有完整的系统来源揭示（如ch451-463），世界观就不能写「来源不需要太多解释」。要么删掉这句话，要么补上完整来源。

### 4. 定价不能反推

先定义物品在现实中的作用 → 估算买家愿付多少 → 给出价格区间。**永远不要**从游戏金币成本反推售价。金币只是通道「运费」，和现实价值无关。

## 命令模板

```bash
# 检查地名一致性
grep -c "宁市" 正文/ch*.md | grep -v ":0" | wc -l

# 检查人名一致性
grep -l "刘建国" 正文/ch*.md | wc -l

# 检查设定文件中过期的描述
grep -n "不需要" 设定/*.md
grep -n "如果能重来" 设定/*.md

# 检查正文中数值是否在设定范围内
grep -oP "\d+万?元" 正文/ch0{01..30}-*.md | sort | uniq -c
```

## Step 5.5：设定修后正文扫描（强制执行）

设定文件改完后，**必须**对全书正文做系统扫描。不能假设「改了设定就行」。扫描分四类：

### A. 数字类修改（价格/数值/比例）

```python
# 正则搜所有章节中的元/块/金币金额，与关键词（药/装备/戒指/裁决等）交叉匹配
# 命中后人工读上下文——多数是营业收入/个人积蓄，不是物品单价
# 只有直接描述「卖了X元」且物品是魔法物品的才需要改
```

### B. 语言类修改（术语替换）

```python
# 搜「建造」/「建立」→替换为「对齐」/「激活」（如果已执行全量替换则验证0残留）
# 搜过期短语如「如果能重来」→必须为0
```

### C. 叙事类修改（人物动机/系统来源）

```python
# 搜过期的来源描述：「不需要太多解释」「规则层面的连通」
# 搜提前泄露的谜底：「39号」不能在ch318之前作为概念出现（但ch304提及名字是铺垫，属正常）
```

### D. 逐卷抽样验证

对每卷抽5-10章快速阅读，确认叙事语气与修改后的设定一致。重点抽查：
- 卷末章（叙事总结容易引用设定文件）
- 系统揭示章（ch180/ch451-463）
- 笔记本/复盘章（角色在总结时容易引用设定语言）
