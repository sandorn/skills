# 批量写作避坑指南

> 实战教训汇总。写章前扫一眼可避免大部分返工。

---

## 避坑 1：初稿字数严重不足

**症状**：写完第一章发现 1500 字，逐轮 patch 加料，一轮只加 200-300 字，6 轮后才到 2500。

**对策**：
1. 初稿瞄准 3200+ 字，不瞄准下限
2. 写到 60% 处检查字数，<1800 字立即插入新场景
3. 每章至少 3 个独立场景（空间/时间切换）

## 避坑 2：「不是…是/而是…」高频无意识犯错（B03 全集）

写完正文后必须扫描以下全部变体：
- `不是…而是…`（经典形式）
- `不是…是…`（短形式，常见于「不是X，是Y」逗号连接）
- `并非…而是…`（文言变体）

判定规则（见 `hard-bans.md` B03）：**逗号/省略号连接的否定→肯定结构 = 违规**。句号断开的「不是X。是Y。」（两句独立短句，各有主语）= 合规。

扫描命令：
```python
import re
# 找所有逗号连接的违规
violations = re.findall(r'不是.{1,30}[，,](?!.*但).{1,10}(?:是|而是)', text)
```

修复：要么拆分句号，要么直接陈述（删除「不是X」）。

## 避坑 3：「他知道」仍是禁令词

用行为或感知替代：❌ "他知道自己接下来要干什么。" → ✅ "他接下来要干什么。"

## 避坑 4：句号断段与长句合并

每个句号后立刻换行，不在脑中预合并。

## 避坑 5：新章与旧章相邻时的审计范围

审计必须覆盖全部指定范围（含旧章），修复不分新旧。

## 避坑 6：节拍表与详细大纲不一致

写章前必做对齐检查。节拍表中的「中段反转」「卷末高潮」「收尾钩子」必须在详细大纲中找到对应实现。

## 避坑 7：主会话逐章写章时逐章审计

写一章审一章，上下文还在当场修复。全写完后再跑一次批量扫描。

## 避坑 8：批量写章后的质检流水线

delegate 返回后立即执行三阶段：
1. 批量破折号清零
2. 批量 AI 句式扫描 + 修复
3. 字数不足修复

## 避坑 9：echo >> 导致模板复制（S1 级事故）

绝对禁止 `echo >>`。字数追加必须用 `pad_chapter.py`。

## 避坑 10：委派 patch 静默失败陷阱

委托后主会话必须抽样验证修复结果。批量机械修复优先在主会话执行。

## 避坑 11：文件写入工具的引号转义残留

全文统一用「」，不受 JSON 转义影响。

## 避坑 12：大纲/设定交叉不一致（写章前必检）

写章前必须跑一次跨设定一致性检查（见 `references/setting-consistency-audit.md`）。常见陷阱：
- 空间戒指容量前后不一（1立方米 vs 3立方米）
- 属性百分比叠加未追踪（力量何时开始加的？）
- 红卡碎片 vs 终极规则卡未分类
- 总纲章节编号与卷章纲不一致
- 卷末资产 ≠ 下卷初资产

## 避坑 13：委派 context 不含核心资产状态

委派子Agent时必须把「当前核心资产清单+属性数值」放入 context，否则子Agent无法做一致性检查。

## 避坑 14：Windows 中文路径文件写入陷阱

`write_file` 工具对含中文字符的路径不可靠（报告成功但文件不落盘）。回退方案：使用 PowerShell 的 `[System.IO.File]::WriteAllText`。

```powershell
$content = @'
正文内容（@''和''@必须顶格）
'@
[System.IO.File]::WriteAllText("D:\Writer\项目\chapters\ch_00N.md", $content, (New-Object System.Text.UTF8Encoding $true))
```

子代理委派时必须在 context 中明确告知此写入方法。

## 避坑 15：文风偏好—轻松烟火气 + 精明底色

主角宜「精明但不冷」：算账时像生意人，说话时像街坊。忌纯文学克制风（留白太多），也忌纯算计风（三笔账式冷分析）。好文风标志：
- 调侃式自嘲（「短剑？削苹果？」）
- 具象比喻接地气（「颈椎僵得像生锈的水管」）
- 判断快而口语化（「他想了两秒。选体质。」）
- 回忆一笔带过不蔓延（失败史一句话，不自怜）

## 避坑 16：开篇慢热——用回忆穿插重构节奏

**症状**：按大纲顺序写，前 4 章都是背景铺垫（入坑/初入/首次刷金/15级），第 5 章才到核心钩子。读者在前 4 章就流失了。

**对策**：把核心钩子提前到第一章，前情用回忆闪回穿插。

**操作步骤**：
1. 识别「真正的第一章」——故事从哪个事件开始不可逆地改变主角命运？比如弹窗出现。
2. 把该事件作为第一章开篇。
3. 在主角面对决策的时刻，通过回忆穿插前情——不是连续回忆，是碎片化闪回。
4. 删除原第 1-N 章，将内容压缩为回忆片段散落在新第 1-2 章中。

**警告**：重构后必须同步更新所有大纲、编号、角色登场节点、伏笔表。大纲中旧 ch1-N 的内容需标注「已融入回忆穿插」。

## 避坑 17：声音不匹配——3 轮重写定调模式

**症状**：写出来的文风与读者/平台偏好不匹配。用户说「文风不喜欢」但说不清具体哪里不对。

**常见失败路径**：
- 第 1 版：文学克制风（独句留白、情感内敛、意识流收尾）→「太冷」
- 第 2 版：精明算计风（三笔账式分析、策略推演）→「太像投行报告」
- 第 3 版：轻松烟火气（日常吐槽、接地气比喻、自嘲）→ ✅

**对策——三轮收敛法**：
1. 第 1 轮：写出后让用户一句话评价——「读起来像谁在讲故事？」
2. 第 2 轮：根据反馈彻底重写（不修修补），换一个极端方向试探边界
3. 第 3 轮：收敛到两个极端的中间地带，保留优点、剔除缺点

**定调后必须做的事**：
- 创建 `setting/writing_rules.md` 固化声音指引
- 确保后续所有章节和委派子代理都加载该文件
- 在 SKILL.md 路由表中追加该文件检查

## 避坑 18：批量 AI 词替换脚本的「不」→「是」污染

**症状**：用 Python 脚本对全卷执行 `text.replace('突然', '猛地')` 等批量替换后，发现章节中出现大量「是是」「是疼」「是胀」等乱码。原来是「不」被系统性替换为「是」。

**原因**：替换链中存在意外副作用。例如 `text.replace('不是', '是')` 会将正常的「不是」破坏为「是是」，随后其他替换规则进一步扩散污染。

**对策**：
1. 批量替换前先 `grep` 目标模式在所有章节中的出现次数，建立基线
2. 逐章执行替换（非全卷），每章替换后立即审计
3. 先用正则 `\b` 边界限制替换范围
4. 替换后扫描「污染标记」（如异常高频的「是是」）
5. 保留替换前的原始文件副本

**检测污染**：
```python
import re, os
for fn in os.listdir('chapters'):
    text = open(f'chapters/{fn}').read()
    if text.count('是是') > 0 or text.count('是疼') > 0:
        print(f'CORRUPTED: {fn}')
```

**修复策略**：靶向替换——只修复确认受污染的章节，用 `是是→不是`、`是疼→不疼` 等精准规则逐条恢复。不重新执行原始替换链。

## 避坑 19：逐章文风审查不可加速——禁止用脚本/子代理替代逐章通读

**症状**：用户要求「逐章检查文风、语气」，但审查者用 Python 脚本做自动化扫描后快速跳过，或在读到一半时切换到脚本加速。用户立刻指出——「你为啥要加速，你有啥着急的活」「逐章检查，不使用子代理，不用脚本，检查一章报告一章」。

**根本原因**：文风和语气是审美判断，不是规则匹配。自动化扫描能发现「禁令违规」「字数不足」「污染残留」，但无法判断「这句话读起来像张远说的吗」「这段独白是不是太冷了」「这里的节奏对不对」。这是人（或 LLM 精读）才能做的事。

**硬性规则**：
1. 用户说「逐章检查文风、语气，不用子代理，不用脚本」→ **逐章通读全文**，不能扫描代替
2. 每章读完→立刻报告：语调评估 + 发现的问题 + 是否需要修复
3. 一章未读完不跳到下一章
4. 不因「前面几章都没问题」而假设后续也没问题——每章独立判断
5. 即使前 N 章全部清空，也不能切换到批量扫描模式。用户明确禁止时，必须坚持逐章通读直到终点

**报告格式**（每章一条）：
```
通读完成。
**语调**: ✅/⚠️ [一句话评估]
**问题**: [无 / 具体问题 + 修复]
---
```

**为什么不能用子代理**：子代理没有本次会话的上下文——不知道前面章节的语调细节、不知道用户刚刚修正过的偏好、不知道这场对话里形成的默契。逐章审查是连续性的审美判断，换人会断。

**与 quick 模式的关系**：`review --quick` 是写章过程中的自检工具（纯规则扫描，30 秒），不是逐章文风审查的替代品。`review --daily` 同理。当用户明确要求「逐章检查文风、语气」时，唯一正确的方式是人工（或主会话 LLM）通读。
