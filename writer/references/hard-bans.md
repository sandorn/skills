# 硬性禁令（单一事实来源）

本文档是 writer skill 所有禁令的**唯一权威定义**。SKILL.md、README.md、quality.md 均通过引用本文档获取禁令列表，不再各自维护副本。

---

## 禁令层级

| 层级 | 含义 | 违规处理 |
|------|------|---------|
| **P0 阻塞** | 必须清零，有一条即不可发布 | 阻断，修完再继续 |
| **P1 强制** | 强烈要求遵守，极少例外 | 阻断（批量质检）/ warning（单章日更） |
| **P2 建议** | 推荐遵守，允许有理由的例外 | warning + 标注原因 |

---

## P0 阻塞禁令（5 条）

### B01 — 对话引号必须用「」

正文中所有对话必须使用 `「」`，禁止以下形式：

```
❌ "你好。"         ASCII 双引号
❌ "你好。"         Unicode 弯引号 (U+201C / U+201D)
❌ '你好。'         ASCII 单引号
✅ 「你好。」
```

**注意**：`「」` 是 Unicode 单字符，不受文件写入工具的 JSON 转义影响，根治转义残留。

### B02 — 破折号清零

正文中不得出现 `——`。替换为逗号 `，` 或句号 `。`。

```
❌ 他站了起来——然后又坐下。
✅ 他站了起来，然后又坐下。
```

**例外**：对话中表示被打断的单条 `——`（半角水平）可保留，但必须在审查阶段标注。

### B03 — 「不是…而是…」句式禁用

不得用否定→肯定的对比结构推动论点。

```
❌ 不是他不想去，而是去了也没用。
✅ 去了也没用。
```

**判定范围**：用逗号/省略号粘合成单句的「不是…而是…」结构。句号断开的「不是X。是Y。」（两句独立短句）不在禁令范围。

### B04 — 元叙事标签禁用

不得出现跳出故事的叙述语句。

```
❌ 正如前文所述……
❌ 读者可能已经猜到……
❌ 这里需要补充一下……
❌ 在这个场景中……
```

### B05 — AI 高频词禁用

以下词汇和句式在正文中**零容忍**：

| 违禁词 | 替换方向 |
|--------|---------|
| `他知道` | 删除或改为动作展示 |
| `忽然` | 猛地 / 一瞬 / 骤然 |
| `突然` | 一下子 / 毫无征兆地 |
| `眼中闪过一丝` | 垂下眼 / 别开目光 / 眼神变了 |
| `深吸一口气` | 缓了缓 / 顿了顿 / 胸膛起伏了一下 |
| `心中一动` | 心头一跳 / 念头一闪 |
| `似乎` | 好像 / 像是 / 删除（直接陈述） |
| `仿佛` | 像 / 如同 / 删除（直接陈述） |

**项目扩展**：若项目 `setting/writing_rules.md` 或 `设定/写作规范.md` 定义了额外的 AI 高频词（如 `某种…的感觉`、`如潮水般`），以项目规范为准，追加到 B05 清单。

## P1 强制禁令（4 条）

### B06 — 段落按句号断段

- 每段 ≤60 汉字（对话和内心独白除外）
- 段落间保留一个空行
- 段落拆分必须用 `split_paragraphs.py`，禁止手工拼接

### B07 — 每章 ≥2500 汉字

- 统计口径：仅计中文汉字（Unicode `一-鿿` 范围），不含标点/空格/换行
- 字数不足时，必须用 `pad_chapter.py` 追加，**禁止 `echo >>`**（会导致超长段落 + 模板复制）

### B08 — 字数追加必须使用 pad_chapter.py

- 禁止 `echo >>`、禁止手工批处理追加
- `pad_chapter.py --batch 正文/` 一步完成追加 + 段落拆分 + 跨章去重

### B09 — 子代理委派批次上限

- 单次子代理委派（sub-agent delegation）最多 10 章
- 超过 10 章拆分为多批，推荐每批 5 章（写章）
- 审查任务每批最多 40 章（审查比写章省迭代预算）
- 超过上限易触发迭代预算耗尽/超时，且产出质量显著下降

## P2 建议禁令（1 条）

### B10 — 写新卷前卷间衔接检查

进入新卷前，验证跨卷衔接的 7 项（详见 `references/deploy.md`）：
时间 / 情节 / 等级 / 金币 / 权限 / 角色位置 / 情感弧线

## 质检时的项目规范覆盖

质检流程启动时，按以下优先级加载禁令：

1. 读取本文件（基线）
2. 检测 `setting/writing_rules.md` 或 `设定/写作规范.md`
3. 若项目文件定义了更严格的禁止词 → **以项目规范为准**，追加到 B05 清单
4. 若项目文件未定义额外规则 → 仅使用本文件基线

此覆盖机制确保：全局底线统一 + 项目特化灵活。
