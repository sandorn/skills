本文档是 writer skill 所有禁令的**唯一权威定义**。SKILL.md、README.md、quality.md 均通过引用本文档获取禁令列表，不再各自维护副本。

---

## 禁令层级

| 层级 | 含义 | 违规处理 |
|------|------|---------|
| **P0 阻塞** | 必须清零，有一条即不可发布 | 阻断，修完再继续 |
| **P1 强制** | 强烈要求遵守，极少例外 | 阻断（批量质检）/ warning（单章日更） |
| **P2 建议** | 推荐遵守，允许有理由的例外 | warning + 标注原因 |

---

## P0 阻塞禁令（6 条）

### B01 — 对话引号必须用「」

正文中所有对话必须使用 `「」`，禁止以下形式：

```
❌ "你好。"         ASCII 双引号
❌ "你好。"         Unicode 弯引号 (U+201C / U+201D)
❌ '你好。'         ASCII 单引号
✅ 「你好。」
```

**注意**：`「」` 是 Unicode 单字符，不受文件写入工具的 JSON 转义影响，根治转义残留。

### B02 — 破折号清零

正文中不得出现 `——`。替换按上下文四类处理，**禁止粗暴全局替换为单一标点**（会破坏对话中断、拟声等效果）：

| 上下文模式 | 识别特征 | 替换为 |
|-----------|---------|-------|
| 拟声词 | `"哗啦——"` / `嗡——` / 前后紧邻拟声字+闭合引号/换行 | 句号：`"哗啦。"` / `嗡。咚。` |
| 对话中断 | 「XXX——」 / 破折号后紧跟闭合引号（」"”） | 省略号：`「XXX……」`（话没说完） |
| 解释说明 | 句中 `A——B`（B是A的展开，前句是完整短语） | 句号断开 `A。B` 或逗号 `A，B`（根据前文标点） |
| 独立转折 | 行首 `——XXX`（单独成段的口型/字幕/心理转折） | 删除破折号直接起句：`XXX` |

```
❌ 他站了起来——然后又坐下。
✅ 他站了起来，然后又坐下。
❌ "哗啦——"水花炸起
✅ "哗啦。"水花炸起
❌ 「你——」赵铁瞪大了眼
✅ 「你……」赵铁瞪大了眼
❌ ——活着回来。（单独行表口型）
✅ 活着回来。
```

**注意**：
- 拟声词识别正则：`[嗡咔咚当哐哗吱呀呵啦嘿]——[""」\r\n]`
- 对话中断识别正则：`——[""」”]`（破折号后紧跟闭合引号）
- 行首转折识别正则：`[\r\n]+\s*——`（行首仅空白+破折号）
- 其余为解释说明，按句末/句中分别用句号/逗号

**例外**：对话中表示被打断的单条 `——`（半角水平）可保留，但必须在审查阶段标注。

### B03 — 「不是…而是…」及其变体禁用（排比堆砌判定）

不得连续使用否定→肯定对比结构推动论点。**判定阈值：单句独立使用不违规，单章≥3处或相邻2句连续排比视为违规**。

```
❌ 不是他不想去，而是去了也没用。（单句弱违规，允许但不推荐）
❌ 不是被吓到，而是在辨认。不是因为害怕，而是在等待。（相邻排比 → 违规）
❌ 不是因为感情，而是因为得还。不是为了过去，而是为了将来。（连续排比 → 违规）
✅ 去了也没用。
✅ 他在辨认。
✅ 不是感情债。是数目。得还。（句号断开两句独立短句，不在禁令范围）
```

**判定范围**：
- 违规：逗号/破折号连接的「不是X，而是Y」单句且单章≥3处，或相邻两句形成排比
- 不违规：句号断开的「不是X。是Y。」（两句独立短句，各有主语）
- 不违规：纯功能性动作描写（如「不是扑向A，而是侧身冲向B」），这是正常叙事对比，非论点推动

### B04 — 元叙事标签禁用

不得出现跳出故事的叙述语句。

```
❌ 正如前文所述……
❌ 读者可能已经猜到……
❌ 这里需要补充一下……
❌ 在这个场景中……
❌ 本书/本章/作者按/笔者/作者我……
```

**正常指代不算违规**：
- `《XX见闻录》的作者是三百年前的金丹散修`（指故事内书籍作者）
- `这封信的作者不明`（指故事内文字作者）
- 判定正则：前面紧邻`的`字的`作者`（如`的作者`）是正常指代，不违规；独立作主语指本书/本文作者才是元叙事

### B05 — AI 高频词禁用

以下词汇和句式在正文中**零容忍**：

| 违禁词 | 替换方向 |
|--------|---------|
| `他知道` | 删除或改为动作展示 |
| `忽然` | 猛地 / 一瞬 / 骤然 |
| `突然` | 一下子 / 毫无征兆地 |
| `眼中闪过一丝` | 垂下眼 / 别开目光 / 眼神变了 |
| `深吸一口气` | 缓了缓 / 顿了顿 / 胸膛起伏了一下 |
| `心中一动` | 心头一跳 / 念头一闪 |
| `似乎` | 好像 / 像是 / 删除（直接陈述） |
| `仿佛` | 像 / 如同 / 删除（直接陈述） |

**项目扩展**：若项目 `setting/writing_rules.md` 或 `设定/写作规范.md` 定义了额外的 AI 高频词（如 `某种…的感觉`、`如潮水般`），以项目规范为准，追加到 B05 清单。

### B11 — Markdown 格式零容忍（章节正文）

`chapters/` 目录下所有 `.md` 章节正文**不得包含 Markdown 语法标记**。番茄小说等发布平台是纯文本渲染，星号井号会字面显示，污染读者体验。

**写章时就要避免，不是发布前才清洗**——包括子代理生成、批量写章、手工润色，全部禁用以下形式：

| 类别 | 违规样例 | 正确写法 |
|------|---------|---------|
| 加粗 | `**关键词**` | `关键词`（或用「」/《》/顿号强调） |
| 斜体 | `*关键词*` | `关键词` |
| 标题 | `# 第1章` `## 场景一` | `第1章` 直接首行；场景切换用空行 |
| 代码 | `` `代码` `` | 删除反引号 |
| 分隔线 | `---` `***` | 空行代替 |
| HTML | `<br>` `<hr>` `<b>` | 全部删除 |
| 链接/图片 | `[文本](url)` `![alt](img)` | 提取纯文本 |
| 引用 | `> 引文` | 删除 `>` 或用「」包裹 |
| 无序列表 | `- 项` `* 项`（正文中） | 用句子写出（大纲/设定文档不受此限） |
| 有序列表 | `1. 项` `2. 项`（正文中） | 用「一是……二是……」等中文序数（大纲不受此限） |

**唯一例外**：章节文件首行的中文标题**不允许**用 `#` 前缀（写作 `第X章 标题`，不写 `# 第X章 标题`），因为大量老稿保留了 `# `——这是仅有的「允许存在但发布前清理」的项。**新写章一律直接首行中文标题、不加井号**。

**检测**：
- 扫描命令：`python scripts/audit.py chapters/`（B11 已纳入）
- 手工快查：`grep -nE '\*\*|^#\s|^\s*[-*]\s|`|<[a-z/]+>' chapters/*.md`
- 一键清洗（应急）：`sed -i -e 's/^# //' -e 's/\*\*//g' chapters/ch_*.md`

**作用范围**：
- ✅ `chapters/**/*.md` —— 正文，B11 生效
- ❌ `outline/**/*.md`、`setting/**/*.md`、`README.md`、`CHANGELOG.md` —— 工作文档，Markdown 允许且鼓励

## P1 强制禁令（4 条）

### B06 — 段落按句号断段

- 每段 ≤42 汉字（对话和内心独白除外）
- 段落间保留一个空行
- 段落拆分必须用 `split_paragraphs.py`，禁止手工拼接

### B07 — 每章 ≥2500 汉字

- 统计口径：仅计中文汉字（Unicode `一-鿿` 范围），不含标点/空格/换行
- 字数不足时：标记该章，由作者或主模型手工扩充（展开场景描写/感官细节/角色反应）
- **禁止**：`echo >>`、脚本注入预制文本、正则批量替换扩充——这些会导致模板复制和文本污染

### B08 — 字数追加禁止脚本注入

- 禁止任何脚本向正文注入预制文本
- 禁止对正文执行正则批量替换（「不→是」「是是」污染的根源）
- 字数不足的唯一合法修复方式：人工/主模型逐章阅读后手工扩充

### B09 — 子代理委派批次上限

- 单次子代理委派（sub-agent delegation）最多 10 章
- 超过 10 章拆分为多批，推荐每批 5 章（写章）
- 审查任务每批最多 40 章（审查比写章省迭代预算）
- 超过上限易触发迭代预算耗尽/超时，且产出质量显著下降

## P2 建议禁令（1 条）

### B10 — 写新卷前卷间衔接检查

进入新卷前，验证跨卷衔接的 7 项（详见 `references/deploy.md`）：
时间 / 情节 / 等级 / 金币 / 权限 / 角色位置 / 情感弧线

## 质检时的项目规范覆盖

质检流程启动时，按以下优先级加载禁令：

1. 读取本文件（基线）
2. 检测 `setting/writing_rules.md` 或 `设定/写作规范.md`
3. 若项目文件定义了更严格的禁止词 → **以项目规范为准**，追加到 B05 清单
4. 若项目文件未定义额外规则 → 仅使用本文件基线

此覆盖机制确保：全局底线统一 + 项目特化灵活。
