# 纯手动逐章逐段润色模式

完全规避子代理并发卡死问题，100% 可控的润色模式，所有改动都是主 AI 模型在当前会话上下文里亲手完成的。

---

## 核心原则

### 三零原则

1. **零脚本**：全程不调用任何脚本工具（不执行 `python3 audit.py` / `pad_chapter.py` / `split_paragraphs.py` 等）
2. **零子代理**：完全不使用子代理委派（sub-agent delegation），不 spawn 任何子 Agent
3. **零批量自动替换**：不使用 sed/awk/正则批量替换，每处改动都是逐句阅读后的手动判断

### 子代理边界（防破窗指引）

「零子代理」不是口号，是每一章都要守住的底线。以下场景是常见破窗点——AI 容易自我合理化"这不算是子代理"：

| 诱惑场景 | ❌ 破窗做法 | ✅ 正确做法 |
|---------|-----------|-----------|
| 检查章节字数是否 ≥2500 | 调 `pad_chapter.py --check` 或 spawn 子代理统计 | 主模型肉眼估算：行数 × 每行平均字数；不确定时多算一遍 |
| 扫描 AI 高频词 | 调 `audit.py` 或 `grep` 批量扫 | 逐句阅读时眼睛自带扫描——读完一章你自然知道哪些句子不对劲 |
| 检查段落超长 | 调 `split_paragraphs.py --dry-run` | 逐段目测：超过 3 行的段落基本超标，手动拆分 |
| 批量统计优化点 | spawn 子代理逐章统计 | 润一章记一章，进度文件手动累加，不靠事后回忆 |
| 章末钩子力度评分 | 调 `analyze_hook.py` | 对照技法手册 4.3 节四条标准，人工判断 |
| 对话引号批量检查 | `grep '"'` 扫 ASCII 引号 | 润色时逐句改写对话，引号自然同时修正 |
| 「似乎/仿佛」密度统计 | `grep -c` 计数 | 读的时候感觉到"这个词出现太多了"——直接删，不需要精确计数 |
| 章节润后字数不足，需要补 | 调 `pad_chapter.py` | 主模型写补充内容：找该章最薄弱的场景，展开 1-2 段画面描写 |

**底线规则**：
- 不通过子代理执行任何 Python 脚本
- 不通过子代理读取/分析文件内容（即使 agent_type 为只读）
- 所有质量判断由主模型在上下文中完成
- **宁可漏判一处，不可开子代理的口子**——漏判只影响一章，破窗影响全书

### 润色哲学

- **微调而非重写**：每章改动控制在 5-15%，避免"越改越不像原文"
- **增强而非替换**：在原文基础上提升画面感和爽点节奏，不替换作者的表达习惯
- **保真优先**：宁可少改一处，不可改错一处。不确定的改动 → 保留原文
- **润色 ≠ 只修禁令**：画面感、节奏、对话、信息密度四个维度必须全部覆盖。不能把「纯手动润色」降级为「禁令扫描 + 污染修复」——那样等于没做润色。

## 常见陷阱与教训

### 陷阱一：「不→是」污染（批量修复脚本后遗症）

**症状**：大批章节中「不」被替换为「是」，如「不疼」→「是疼」、「不知道」→「是知道」、「不了」→「是了」。

**成因**：使用正则或 `replace('不是', '')` 式的批量修复脚本时，替换逻辑不精确，误伤了正常文本。

**检测方法**：逐章通读时，用眼睛扫描以下高频误伤模式：
- `是疼` `是胀` `是错` `是到` `是敢` `是急` `是能` `是像`
- `是起` `是懂` `是够` `是怕` `是对劲` `是知道` `是同意`
- `是正常` `是清楚` `是会` `是服` `是响` `是酸` `是爽`

**修复原则**：逐处判断上下文，只修明确误伤的，不再次批量替换。

### 陷阱二：把禁令审查当润色

**症状**：通读后只修了破折号、AI高频词、B03违禁句式，没有对画面感、节奏、对话做任何创作性增强。

**判断标准**：如果一章润完后，没有新增任何感官细节、没有调整任何句长节奏、没有优化任何对话标签——那就是没润，只是审。

**正确做法**：禁令修复是润色的**前置步骤**，不是润色本身。每章至少标记并执行 3-5 处创作性微调。

### 陷阱三：用自动扫描替代逐章报告

**症状**：写一个 Python 脚本扫描所有章节，批量输出结果，一次性报告几十章。

**用户反感信号**：「你为啥要加速」「不能逐章报告吗」「不用脚本」。

**正确做法**：每章独立通读→独立标记→独立修复→独立报告。一章一帖，不给用户「你在偷懒」的感觉。

### 陷阱四：把「润色」降级为「禁令修复 + 污染清除」

**症状**：通读后只修了破折号、AI高频词、B03违禁句式、「不→是」污染残留，没有对画面感、节奏、对话做任何创作性增强。报告只有「N处污染+N处润色」但没有改前→改后例句。

**用户反感信号**：「这些不符合手动润色的要求」「你是不是只做了禁令审查」

**判断标准**：如果一章润完后，维度报告中没有画面/节奏/对话/密度任一列的具体数字和改前→改后例句——那就是没润，只是审。

**正确做法**：禁令修复和污染清除是润色的**前置步骤**，不是润色本身。每章至少标记并执行 3 处创作性微调，并在报告中给出具体例句。

## 硬性规则（必须严格遵守）

### 润色操作规范

1. **全量逐章阅读**：每章完整读完至少一遍，理解上下文后再动笔
2. **逐句微观调整**：只优化措辞、语气、语态，不动核心情节
3. **画面感+爽点节奏**：优化目标是提升画面感和爽点节奏
4. **核心情节 100% 不动**：所有原始情节、人物对话、结构框架完整保留
5. **一章一结**：每章润完立即写回，不攒到内存批量写
6. **优化点实时记录**：每章改完后立即记录优化点，不靠事后回忆

### 交付规范

1. **统一交付**：全部润完后统一汇总给用户确认
2. **中途不打断**：润色过程中不打扰用户，不输出中间状态（除非遇到阻塞问题）
3. **交付报告**：润完后提供完整的交付报告（含逐章明细）

### writer 硬性禁令（润色中同步遵守）

1. **破折号清零**：正文中不得出现 `——`
2. **「不是…而是…」句式禁用**
3. **元叙事标签禁用**
4. **对话必须用 `「」`**：不得出现 `"..."` 或 `'...'`
5. **AI 高频词禁用**：他知道/忽然/突然/眼中闪过一丝/深吸一口气/心中一动/似乎/仿佛
6. **段落按句号断段**：单段 ≤60 汉字
7. **每章 ≥2500 汉字**

## 润色技法手册

### 技法一：画面感增强

目标：让读者"看到"场景，而非仅仅"知道"发生了什么。

#### 1.1 具象化抽象动词

| 原文模式 | 润色方向 | 示例 |
|---------|---------|------|
| 他生气了 | 加入肢体/表情细节 | → 他攥紧拳头，指节发白 |
| 房间很乱 | 具体描述乱象 | → 桌上堆着三天没洗的碗，窗帘半挂着，一只拖鞋翻在床头 |
| 她很漂亮 | 挑选一个特征放大 | → 她笑起来眼尾微微上挑，像只刚睡醒的猫 |
| 战斗很激烈 | 用一个特写镜头 | → 灵力碰撞的余波震碎了方圆十丈的石板 |

#### 1.2 五感注入

每 300-500 字至少激活一种感官（视觉之外）：

- **听觉**：风声、脚步、器物碰撞、呼吸节奏
- **触觉**：温度变化、材质质感、疼痛具体位置
- **嗅觉**：血腥味、药草香、雨后的泥土气
- **味觉**：血的铁锈味、灵液的甘涩

```
❌ Before: 他走进山洞，感觉里面很阴冷。
✅ After:  他踏入山洞，一股湿冷的寒气顺着脚踝爬上脊背，
           空气中弥漫着苔藓腐败的腥甜。
```

#### 1.3 场景留白

不需要把每个细节都写满，挑选 2-3 个锚点细节，其余留给读者脑补：

```
❌ Before: 这是间豪华的办公室，红木办公桌、真皮转椅、水晶吊灯、
           墙上挂着名画、地上铺着波斯地毯、角落里还有一台
           咖啡机和一个书架。
✅ After:  红木办公桌上搁着一只没拧上盖的钢笔，墨迹浸透了
           桌角的合同。水晶吊灯亮着，但窗帘拉得严严实实。
```

#### 1.4 特殊场景对照表（重生/都市文高频场景）

| 场景类型 | 常见平淡写法 | 画面感增强方向 |
|---------|------------|--------------|
| 主角觉醒 | 他睁开眼睛，发现自己重生了 | 加入环境锚点：教室的粉笔灰味、老式吊扇的咯吱声、同桌的旧校服 |
| 打脸装逼 | 对方哑口无言 | 镜头切围观者：周围几个同学偷偷掏出手机，有人已经开始录像 |
| 财富碾压 | 他买了一辆豪车 | 从他人的反应写：4S 店销售扫了一眼他的校服，笑容僵在脸上 |
| 战力突破 | 他突破了 | 身体感受具象化：丹田像被烧红的烙铁捅穿，全身经脉一起痉挛 |
| 感情互动 | 她脸红了 | 微动作：她低头翻了一页根本没在看的书，耳尖透出粉色 |

### 技法二：爽点节奏优化

#### 2.1 爽点句不缩不藏

爽点句是读者翻页的动力，必须给足空间，不让其他信息挤占。

```
❌ Before: 他随手刷卡买下了整栋楼，然后回了教室继续上课。
           // 爽点"买下整栋楼"被压缩成半句，冲击力不足

✅ After:  他掏出那张黑金卡，往柜台上一搁。
          「刷卡。」
          柜员愣了一下，低头看了眼屏幕上的数字——
          八千万，全款。
          她的手指在键盘上顿了足足三秒，才小心翼翼地问：
          「先生……您确定？」
          // 爽点被拉伸成一个独立场景
```

#### 2.2 节奏三拍子

关键爽点场景采用**铺垫→爆发→余韵**三段式：

- **铺垫**（1-2 段）：制造预期。对手先亮底牌/围观者先嘲/主角先示弱
- **爆发**（核心段）：翻转发生，用短句+特写镜头，不给读者喘气
- **余韵**（1 段）：他人的反应/主角的内心独白/下一关的暗示

```
节奏示例（装逼打脸场景）：
[铺垫] 「这小子完了，王少的钱能砸死他。」旁边有人嘀咕。
        王铭把车钥匙往桌上一拍，「认输吧，别丢人了。」
[爆发]  陈默没说话。
        他掏出手机，打开银行 APP，调出余额——
        九位数。
        他把屏幕转向王铭。
[余韵]  包厢里安静了整整五秒。
        王铭手里的车钥匙滑到了地上，他忘了捡。
```

#### 2.3 密度检查

每 1000 字至少一次微型爽点（反差/认可/碾压），每 3000 字至少一次中大型爽点：

| 爽点类型 | 识别特征 | 润色强化方向 |
|---------|---------|------------|
| 战力碾压 | 主角轻松击败对手 | 强化对手的震惊反应+围观者的认知颠覆 |
| 财富碾压 | 主角拿出巨款/买下昂贵物品 | 强化他人从怀疑→震惊→畏惧的转折 |
| 智力碾压 | 主角看破阴谋/解出难题 | 强化对手的自信铺垫→被拆穿后的失态 |
| 身份揭晓 | 隐藏身份被曝光 | 延长曝光瞬间，多角度写不同人的反应 |
| 情感回馈 | 感情线进展/女主态度转变 | 强化内心独白+小动作 |

#### 2.4 句长控制

- **动作场面**：短句为主（5-15 字），制造紧迫感
- **心理活动**：中句（15-30 字），保持流畅
- **环境描写**：中长句（20-40 字），营造氛围
- **爽点爆发**：极短句（3-8 字），一击入魂

### 技法三：对话自然度

#### 3.1 对话标签弱化

减少"XX 说/道"的生硬标签，用动作替代引导：

```
❌ 他说：「你确定？」
✅ 他皱眉：「你确定？」

❌ 她回答道：「我不去。」
✅ 她把头扭到一边：「不去。」

❌ 王铭冷冷地说：「你等着。」
✅ 王铭攥紧了手机，从牙缝里挤出来：「等着。」
```

#### 3.2 口语化校准

检查对话是否符合角色身份和情绪状态：

| 角色身份 | 口语特征 |
|---------|---------|
| 高中生 | 短句多、语气词多（吧/呢/啊/哈）、时而中二 |
| 班主任/长辈 | 说教句式、重复强调、用"啊""嘛"收尾 |
| 校花/高冷女主 | 句短、话少、不解释、偶尔用反问 |
| 混混/反派 | 脏话口头禅、挑衅反问、话多且嚣张 |
| 系统/金手指 | 机械感、精确数字、无情绪语气词 |

#### 3.3 对话节奏

- 两人对话：每轮 1-3 句为佳，不超过 5 句
- 多人对话：每轮切镜头，避免两人连说多轮其他人沉默
- 心理活动穿插：每 3-4 轮纯对话后插入一句主角内心反应

### 技法四：信息密度控制

#### 4.1 删冗余修饰

```
❌ 他的心中忽然涌起了一股难以言喻的复杂感觉。
✅ 他说不清心里是什么滋味。

❌ 这个举动无疑是具有极其重大的意义的。
✅ 这个举动意味着一切都不一样了。

❌ 在那一刻，他终于明白了那个他一直都没能想明白的道理。
✅ 他忽然明白了。
```

#### 4.2 补信息断层

检查是否缺了读者需要知道的信息：

- 新角色登场 → 有没有外貌/身份锚点（哪怕一句）
- 新地点切换 → 有没有空间定位（室内/室外/白天/晚上）
- 时间跳转 → 有没有"三天后""一周后"标记
- 战力/等级变化 → 有没有数值确认

#### 4.3 钩子力度检查

每章末 500 字必须满足至少一项：

- **悬念钩**：抛出一个读者立刻想知道答案的问题
- **反转钩**：刚要结束→突然新信息颠覆认知
- **威胁钩**：主角面临一个必须解决的紧迫危机
- **期待钩**：预告明天有大事发生/即将获得奖励

```
❌ 章末弱钩: 他躺在床上，想着明天还要上课，很快睡着了。
✅ 章末强钩: 他刚闭上眼，手机亮了。
            一条短信，只有六个字：
            「游戏开始了。——系统」
```

## Before/After 完整示例

### 示例一：画面感增强（战斗场景）

**Before（平淡叙述）**：
> 陈默一掌拍出，强大的灵力直接将对面的妖兽击飞出去。
> 妖兽撞在墙上，发出一声巨响，然后就倒在了地上。

**After（画面感增强 + 句长控制）**：
> 陈默一掌拍出。
> 掌风未至，空气已经被压出了爆鸣声。
> 那头铁甲犀像被一座山迎面撞上——四蹄离地，七百斤的兽躯
> 在空中翻了两圈，轰然砸进岩壁。碎石飞溅，尘土中传来一声
> 低沉的哀嚎，然后彻底安静了。

**改动说明**：
- 抽象"强大的灵力"→ 具象"空气被压出爆鸣声"
- 短句拆解动作节奏
- 增加听觉（爆鸣/轰然/哀嚎）和视觉（碎石/尘土）
- 加入数字锚点（七百斤/两圈）

---

### 示例二：爽点节奏优化（打脸场景）

**Before（爽点被压缩）**：
> 王铭嘲笑道：「你一个穷学生配和本少爷争？你知道我家有多少钱吗？」
> 陈默直接打开手机，上面显示余额九位数，王铭顿时说不出话了。

**After（三拍子结构）**：
> 王铭笑了。「你一个穷学生，拿什么跟本少爷争？」
> 他把保时捷的钥匙扔到桌上，靠进椅背里。「认个怂，不丢人。」
> 周围几个女生偷偷看向陈默，眼神里全是同情。
>
> 陈默没说话。
> 他掏出手机，点开银行 APP。
> 递过去。
>
> 王铭扫了一眼——
> 笑容僵住了。
> 余额那一栏，数字长得他一时没数清楚。
> 个、十、百、千、万、十万、百万、千万……
> 亿。
>
> 包厢里安静了。
> 钥匙从桌沿滑下去，叮当一声落在地上，王铭忘了捡。
> 刚才还同情陈默的几个女生，手里的奶茶都端歪了。

**改动说明**：
- 铺垫：王铭的两段嚣张+围观者反应
- 爆发：短句推进，余额从数位逐级揭晓，延长爽点
- 余韵：钥匙落地、奶茶端歪，用细节写众人的震惊

### 示例三：对话自然度（校园场景）

**Before（对话生硬）**：
> 「陈默同学，请你回答一下这个问题。」
> 「老师，我不知道答案。」
> 「那你为什么不认真听讲？」
> 「因为我昨晚没有睡好，所以无法集中注意力。」
> 「这不是理由。」

**After（口语化 + 动作替代标签）**：
> 粉笔头在黑板上顿了顿。
> 「陈默——这道题。」
> 陈默站起来，看了一眼板书。
> 「不会。」
> 王老师眼镜滑到鼻尖：「昨晚上干什么去了？」
> 「没睡好。」
> 「不是理由。」
> 陈默没接话。他总不能说自己昨晚刷了一夜的未来股市数据。

**改动说明**：
- "请你回答一下这个问题"→"这道题"，教师口语
- 加入动作引导（粉笔头顿/眼镜滑/站起来看）
- 学生的完整解释→简短回答，更符合高中生
- 末尾补一句心理活动，给读者信息增量

## 可改 vs 不可改（详细判例）

### ✅ 可以微调的内容

| 类别 | 具体操作 | 力度上限 |
|------|---------|---------|
| 词汇替换 | 精准化动词/形容词，去 AI 高频词 | 一句内 ≤2 词 |
| 句式调整 | 拆分超长句、合并碎片短句、调整语序 | 不改原意 |
| 节奏优化 | 调整句长分布、加入短句停顿 | 不动段落结构 |
| 画面感注入 | 加入感官细节、动作锚点 | 一句 ≤1 处新增细节 |
| 对话标签 | 弱化"说/道"、用动作替代 | 不改对白内容 |
| 删冗余 | 去掉"似乎/仿佛/忽然"等 AI 高频词 | 只删不换原意 |
| 段落拆分 | 长段落按句号拆分 | 不动句序 |
| 钩子增强 | 章末加入/强化悬念句 | 不动已有钩子设计 |

### ❌ 绝对不能改的内容

| 类别 | 具体范围 | 原因 |
|------|---------|------|
| 情节走向 | 主线/支线的推进方向和节奏 | 润色不承担大纲职能 |
| 人物对话内容 | 对白的信息内容、态度立场 | 对话承载角色塑造 |
| 伏笔埋设 | 伏笔的位置、内容、数量 | 动了会连锁断钩 |
| 关键信息点 | 等级/金币/时间/战力数值 | 动了会引发设定冲突 |
| 章节结构 | 章节起止点、场景切换顺序 | 动了需要重新审纲 |
| 爽点位置 | 爽点的触发节点和类型 | 动了会影响追读节奏 |
| 章末钩子 | 钩子的核心悬念内容 | 动了会断卷间钩链 |
| 角色人设 | 角色性格/说话风格/行为模式 | 动了会导致 OOC |
| 金手指设定 | 系统功能/限制/升级规则 | 动了会引发全书设定崩塌 |
| 作者标志性表达 | 作者刻意使用的独特句式/口头禅 | 保留作者风格辨识度 |

### Step 0：启动前检查

1. 确认项目根目录（检测 `writer.json` + `setting/` + `chapters/`）
2. 读取 `writer.json` 获取当前写作状态

### Step 1：确认润色范围

向用户确认（以下信息不全时追问，否则直接执行）：

1. **润色范围**：起止章节（如 ch03-ch60）

   - 爽点节奏优化（默认开启）
   - 对话自然度
   - 信息密度调整（删冗余+补断层）
   - 全维度润色（以上全部）
3. **力度偏好**：
   - 轻（每章改动 ≤5%，几乎看不出改了）

### Step 3：逐章润色循环

对每一章执行以下 8 步：

```
对于每一章：
  ① 读取正文内容 → ② 完整通读一遍
  → ③ 标记微调点 → ④ 执行逐句调整
  → ⑤ 自检清单 → ⑥ 写回文件
  → ⑦ 记录优化点 → ⑧ 更新进度文件
```

#### ③ 标记微调点

通读时在心里标注：

- `[画面]` 此处可加入感官细节
- `[节奏]` 此段句长单一/爽点被压缩
- `[对话]` 标签生硬/不够口语化
- `[冗余]` 可删的 AI 高频词/重复修饰
- `[断层]` 此处缺空间/时间/身份锚点
- `[钩子]` 章末钩子力度不足
- `[污染]` 疑似「不→是」误伤残留

#### 逐章闸门（进入下一章前必须自答，任一为「否」禁止前进）

```
□ 我是否完整通读了本章每一行？（不是跳读、不是扫关键词、不是依赖脚本输出）
□ 我是否在本章中标记并执行了 ≥3 处创作性微调？（画面/节奏/对话/密度四维度，不含禁令修复和污染清除）
□ 我对本章的润色报告是否包含：维度数量表 + 至少一条改前→改后例句 + 禁令自查结论？
```

#### ⑦ 记录格式（在对话中逐章报告，禁止退化）

每章润完后立即在对话中报告。**每章报告至少包含**：
- 一个带具体数字的维度表格（画面N/节奏N/对话N/密度N/污染N）
- 至少一条「改前→改后」的具体例句
- 禁令自查结论

**禁止以下退化形式**：
```
❌ "chXX: ✅ 无污染 1润色"
❌ "chXX-YY 全清，批量完成"
❌ "全清。关键章加画面润色，其余快速过。"
❌ 用脚本扫描结果替代逐章通读报告
```

维度表格格式：

```
## chNN 润色报告

| 维度 | 处数 | 改前→改后示例 |
|------|------|-------------|
| 画面感 | N | 「原句」→「新句」 |
| 节奏 | N | ... |
| 对话 | N | ... |
| 密度 | N | ... |
| 污染修复 | N | ... |
| 禁令 | ✅ | 破折号0/AI词0/B030 |
```
然后更新 `tracking/manual-polish-progress.md` 中的进度行。
□ AI 高频词已清除（他知道/忽然/突然/似乎/仿佛/眼中闪过一丝/深吸一口气/心中一动）
□ 对话全用「」，无 ASCII 引号残留

□ 无「不是…而是…」句式
□ 无元叙事标签
□ 每段 ≤60 汉字
□ 全章 ≥2500 中文汉字
□ 核心情节/对话内容/伏笔未动

#### ⑦ 记录格式

每章润完后记录优化点类型和数量，在进度文件逐章行追加。

## 异常处理

### 中断恢复

润色过程中若会话中断，恢复流程：

1. 读取 `tracking/manual-polish-progress.md`
2. 找到最后一个状态为 `✅` 的章节
3. 从下一章 `⏳` 或 `🔄` 继续
4. 如果某章状态 `🔄`（润色中但未完成）：
   - 读取该章当前内容，从 `git diff`（如有）或文件修改时间推断已完成部分
   - 若无法确定进度，该章重新润一遍（开销小，不会重复犯错）

```
中断恢复检查清单：
□ 进度文件存在 → 读取续润
□ 进度文件不存在 → 扫描 chapters/ 最后修改时间，推断进度
□ 无法推断 → 从范围起始章重新润（三零原则保证无副作用）
```

### 误改回滚

- 每次润色前，建议先 `git add` / `git commit`（如项目有 git）
- 若无 git，润前先留一份原始备份：`cp chapters/ch_xxx.md chapters/ch_xxx.md.bak`
- 发现某章改坏 → 从备份恢复，重润该章

### 用户中途叫停

- 收到用户叫停指令时，立即完成当前章的自检+写回+进度更新
- 不保存中间状态的润色结果
- 告知用户已完成到第几章

### 润色效果不佳

- 如果某章润后字数变化 >20%，说明改动过重，应检查是否越界到"重写"
- 如果某章润后字数 <2500，必须标记为阻塞，不可交付
- 如果连续 3 章优化点 <5 处，说明润色力度偏轻，和用户确认是否提高力度

## 与其他润色模式的关系

| 模式 | 子代理 | 脚本 | 批量替换 | 可控性 | 适用场景 |
|------|--------|------|----------|--------|---------|
| **纯手动逐章逐段** | ❌ | ❌ | ❌ | 100% | 作者对质量极度敏感/需要逐句掌控 |
| 全量优化（optimize.md） | ✅ | ✅ | ✅ | 中 | 批量提升效率优先，接受自动化 |
| 去AI味（quality.md deslop） | ❌ | ✅ | ✅ | 高 | 针对性清除 AI 痕迹 |
| 审查修订（review → revise） | ✅ | ✅ | ✅ | 中高 | 审查驱动的定向修复 |

选择指引：
- **精准度 > 速度** → 纯手动润色（本文件）
- **效率 > 完美** → 全量优化（`optimize.md`）
- **只需去 AI 味** → quality.md deslop（`quality.md`，适用 ≥10 章批量快速清除）
- **审查发现问题后的修复** → review + revise 管线
