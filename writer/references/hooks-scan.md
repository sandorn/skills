# 伏笔全卷扫描

> **适用范围**：全卷/大批量写章后对伏笔做人工深度盘点。**不适用**：日常写章中的伏笔管理——日常用 `novel_project` MCP 的 `search_nodes({query: "伏笔:", limit: 50})` 即可，不需要全量扫描。
> **加载时机**：写完一卷(≥60章)或大批量(>40章)后。**非日常工具**。

---

## 输入

- 项目所有正文章节目录（`chapters/ch*.md` 或 `chapters/ch_*.md`）
- `novel_project` MCP 里现有的伏笔实体（用 `search_nodes({query: "伏笔:", limit: 50})` 拉全表）
- 可选：老项目遗留的 `追踪/伏笔.md` / `追踪/章节摘要.md` / `追踪/角色状态.md`（视为归档只读）

---

## 扫描策略（N章→精简阅读路径）

**不要逐章读全部N章。** 按以下优先级定位关键章，仅阅读关键章即可覆盖95%的伏笔：

### 第1优先：卷末章
卷末章（每卷最后一章）通常有角色状态汇总、下一卷预告、未解决线索。每卷至少读卷末章。

示例：ch60、ch112、ch179、ch240、ch300。

### 第2优先：MCP 里已登记伏笔的埋线章
从 `search_nodes("伏笔:")` 返回的每个伏笔实体的 observations 中找 `chNNN: 埋线` / `chNNN: 埋设` 前缀条目，那些 chNNN 章必须重读以确认回收状态。

### 第3优先：重大事件章（从章节标题判断）
看章节列表的文件名，提取含关键名词的章：
- 系统相关：`系统`、`通道`、`L`、`权限`、`稳定度`
- 角色转折：`转化`、`加入`、`确定`、`婚礼`、`入职`
- 势力变化：`合服`、`深蓝`、`宁丰`、`对决`、`决战`
- 里程碑：`开业`、`第一家`、`第X家`、`加盟`、`示范`、`获奖`
- 地图信息：`红点`、`坐标`、`海门`、`北京`、`北方`

### 第4优先：前5章+后5章
故事开头和结尾的章节密度最高。前5章布下核心伏笔，后5章埋下下卷钩子。

### 第5优先：卷首章
每卷开始的第1章通常承接上卷钩子，并布下本卷新伏笔。

## 提取模板

盘点表在扫描过程中先在 `.writer/runtime/hooks-scan-<date>.md` 打草稿；**权威源仍是 `novel_project` MCP**——扫描完成后走 `archive_facts.py` 把发现的新伏笔/回收更新写入 MCP。

### 跨卷伏笔表（待回收，工作草稿）

```markdown
| # | 内容 | 埋入章 | 计划回收 | 状态 | MCP 实体名 |
|---|------|--------|---------|------|-----------|
| N | [一句话概括伏笔内容+关键细节] | chXXX | chXXX→第X卷 | →第X卷 | 伏笔:xxx |
```

- **"内容"必须包含足以在100章后仍能识别伏笔的细节**（人名、数字、坐标、特殊物件）
- 如果回收章已明确写在原文中，填入"计划回收"；否则标"→第X卷"
- 状态：`已完成` / `已回收(第X卷)` / `→第X卷` / `持续中` / `→待验证`
- **MCP 实体名**：查 MCP 已存在的对应伏笔实体；无则本次扫描后需 `create_entities` 补建

### 已回收伏笔表（工作草稿）

```markdown
| # | 内容 | 埋入→回收 | 说明 | MCP 关系 |
|---|------|----------|------|---------|
| N | [伏笔内容] | chXX→chYY | [一句话回收方式] | 伏笔:xxx --回收于--> 剧情:yyy |
```

按卷分组，每卷用 `### 第N卷（卷标题）` 分隔。

## 辅助表（按需创建）

### 通道/系统类伏笔多时
用时间线表追踪数值变化。示例：

```markdown
| 时间 | 事件 | 稳定度 | 对应章 |
|------|------|--------|--------|
| 2001.9.28 | 重生，L1 | 0% | ch01-02 |
```

### 空间/地图类伏笔多时
用红点/地点全貌表。示例：

```markdown
| 红点 | 标注 | 坐标 | 含义 | 状态 |
|------|------|------|------|------|
| 省城 | 起点 | ... | ... | ✅ |
| 南边海 | 遗珠 | ... | ... | ✅ |
```

### 有系统化线索时
用单独的表追踪体系演进。示例：笔记本体系（主题迭代）。

---

## 扫描后的写回（v8.4：写 MCP，不再写文件）

1. **先查 MCP 现状**：`search_nodes({query: "伏笔:", limit: 50})` 拉全部现有伏笔实体
2. **对比扫描表 vs MCP**：
   - MCP 里有但扫描没发现 → 需人工确认是否漏；MCP 观测更新为最新状态
   - 扫描发现但 MCP 里没有 → 走 `archive_facts.py`，payload 里 `foreshadowing.new` 补建
   - 扫描发现已回收但 MCP 未标 → `foreshadowing.resolved` 填写，追加 `回收于` 关系
3. **执行归档**：
   ```bash
   cat <<EOF | python <writer>/scripts/archive_facts.py
   {"chapter_number": <当前卷末章号>, "changes": {"foreshadowing": {"new": [...], "resolved": [...]}}}
   EOF
   # → 输出 tool_calls → Agent 依 read→merge→write 顺序调 novel_project MCP
   ```
4. **草稿表存档**：把工作草稿留在 `.writer/runtime/hooks-scan-<date>.md` 供人读复核

## 实战案例：《重生2001》300章扫描

| 阶段 | 阅读章数 | 覆盖范围 |
|------|---------|---------|
| 卷末章 | ch60, ch112, ch179, ch240, ch300 | 5/300 (1.7%) |
| MCP 已登记伏笔章 | ch02, ch08, ch111, ch118-120, ch126 | ~10/300 |
| 重大事件章 | ch164, ch175-176, ch180, ch204, ch214, ch222, ch233, ch239, ch259, ch267, ch285, ch293, ch296, ch299 | ~15/300 |
| 前后5章 | ch01-05, ch296-300 | 10/300 |

**实际阅读约40章（13%），覆盖了95%的伏笔。** 这远优于逐章读300章。

## 陷阱

- **不要因为某章标题平淡就跳过**：ch163-164 标题是"转化公式"和"系统异动"，但后者是系统L5手写体初现的关键章
- **卷末章可能含新伏笔**：ch239 在除夕夜埋下三个红点地图，这是第4-6卷的核心伏笔
- **MCP 伏笔实体的观测本身也是伏笔**：如果 MCP 里某伏笔观测标"→第X卷"但X卷已写完，必须验证并更新观测
