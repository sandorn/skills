# 扫榜：跨平台市场分析与选题决策

---

## 核心原则

1. **单本排名不是结论，跨样本重复模式才是信号。** 排行榜只能证明样本存在；必须通过多榜单、多作品和近期数据判断需求强度。
2. **流量型平台和付费型平台看的东西不同：** 番茄看流量和完读率，起点看订阅和追读，晋江看收藏和积分。
3. **扫榜的目的是找到你能写的爆款题材。** 每个方向都要做项目可行性判断。

---

## Phase 1：确认平台和方向

用 `clarify` 确认平台/方向；如果用户已经指定平台或题材，直接进入采集：

- **用户已有方向** → 针对该方向做深度扫榜
- **用户没有方向** → 做全榜概览 + 找趋势
- **用户想跨平台比较** → 做平台对比分析

常用平台：起点中文网、番茄小说、晋江文学城、飞卢、七猫

---

|------|------|------|------|---------|------|
| 1 | | | | | |
| 2 | | | | | |
| ... | | | | | |

### 趋势提取

找出跨作品重复出现的元素：
- **热门题材**：反复出现的题材类型
- **常见设定**：开篇模式、金手指类型
- **书名模式**：热门书名的词法/句式特征
- **卖点分布**：简介中的核心卖点

## Phase 5：输出

### 保存到项目

如用户确认走某个方向，保存为 `选题决策.md` 到工作目录或项目根：

```markdown
# 选题决策报告

扫榜日期：YYYY-MM-DD
目标平台：[平台名]

## 推荐方向

[详细描述]

## 核心卖点

[1-3句话]

## 差异化

[相对于同类作品的不同点]

## 对标参考

[建议参考的2-3本书]
```

### 无项目时的输出

如用户没有项目目录，直接输出分析结论，让用户决定下一步（继续拆文对标，还是开新书）。
