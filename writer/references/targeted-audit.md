# 定向审查：用户指定维度的批量章段审计

适用于用户明确指定审查维度（如"审查攻城战逻辑/商业对抗合理性/感情线节奏"）的批量审查场景。与 `review.md` 的 43 维全量扫描互补：43 维是规则驱动的合规扫描，定向审查是用户意图驱动的质量评估。

---

## 触发条件

- 用户明确列出审查维度（≥3 项）
- 审查范围 ≥10 章
- 用户关心的是叙事/结构/人物质量，而非禁令/格式/AI痕迹

---

## 执行流程

### Step 0：加载全部参考文档

```
必须加载：
- `outline/master_outline.md`
- 对应卷的详细大纲（如 `outline/volume_outline.md`）
- `setting/power_system.md`（金手指/世界观规则）
- `novel_project` MCP：`get_entity_with_relations` 查主要角色（当前位置/属性/关系）
- `novel_project` MCP：`search_nodes("伏笔:")` 查伏笔埋入/回收状态
```

### Step 1：提取审查维度

将用户指定的维度标准化为可评分的检查项，每项定义：
- 评估标准（什么叫"好"）
- 证据来源（正文哪些章节、大纲哪些节点）
- 评分方式（★ 1-5）

### Step 2：通读目标章节

按顺序读取全部目标章节（分批读，每批5章）。读完后形成对段落质量、节奏、场景分配的整体感知。

### Step 3：大纲-正文对照

逐章与大纲节点比对：
- 事件是否按大纲发生
- 章节号是否与大纲对齐
- 正文扩展/删减了哪些内容
- 记录所有章节号偏移

### Step 4：逐维度评分

每维度输出：
- ★★★★★ 评分（5星制）
- 评分理由（引用正文具体段落或大纲节点作为证据）
- 存在问题（如有）

**评分参考**：
| ★ | 含义 |
|----|------|
| ★★★★★ | 优秀，超出预期 |
| ★★★★☆ | 良好，有小瑕疵 |
| ★★★☆☆ | 合格，有明显可改进处 |
| ★★☆☆☆ | 不足，需要较大修改 |
| ★☆☆☆☆ | 严重问题，需重写 |

### Step 5：输出报告

```markdown
## 审查报告：ch{START}-{END}

### 一、整体评估
{2-3句总体印象，点出最突出的优点和问题}

### 二、分项逐条审查

#### 1. {维度名称}
**评分：★★★★★（优秀/良好/合格/不足/严重）**
- 合理之处：...
- 可商榷之处：...
- 存在问题：{无/具体问题}

#### 2. ...
{重复上述格式}

### 三、大纲-正文对比与结构性问题
{章节号偏移表、内容偏差记录}

### 四、关键质量指标评估
| 维度 | 评分 | 说明 |
|------|------|------|
| {维度1} | ... | ... |

### 五、总体结论
{总结性陈述 + 改进建议清单}
```

## 与 43 维 review 的关系

| | 定向审查 (targeted-audit) | 43维 review (review.md) |
|---|---|---|
| 触发方式 | 用户指定具体维度 | agent 按模式自动选择 |
| 范围 | ≥10章批量 | 单章/批量 |
| 关注点 | 叙事质量/结构/人物/商业逻辑 | 规则合规/禁令/格式/AI痕迹 |
| 输出格式 | 维度评分 + 证据引用 | S1-S4 分级问题清单 |
| 耗时 | 完整通读+评估，较重 | solo/lean 模式较轻 |

**两者互补**：定向审查跑完后再接 `review --quick` 做禁令+格式扫描，形成完整审计闭环。

## 常见审查维度速查

用户常提出的审查方向及对应关注点：

| 用户维度 | 应检查的具体内容 |
|---------|----------------|
| **结构一致性 / 终审** | 时间线连续性、等级单调性、金手指数值合规、每5-10章节奏爽点、大纲偏离度（5维，优先于叙事审查执行） |
| 时间线 | 逐章时间锚点提取、日期倒退检测、章节间时间过渡连贯性 |
| 等级/升级节奏 | 逐章等级记录、单调性检查、权限跃迁触发、升级速度合理性 |
| 金手指合规 | 使用次数/金币消耗/额度统计、越级检测、余额崩坏检测 |
| 攻城/战斗逻辑 | 战术合理性、人数差处理、信息差利用、胜败因果 |
| 商业对抗合理性 | 手段是否符合时代背景、对手反应是否合理、主角反制是否有证据链 |
| 谈判张力 | 双方筹码对等性、信息不对等利用、心理博弈层次、台词的信息密度 |
| 感情线节奏 | 升温节点间距、是否与事业线错峰、是否有实质性事件推动（非纯对话） |
| 卷末牵引力 | 是否埋下下一卷核心冲突、是否完成本卷情感/商业/游戏线的阶段性收束、章末钩子是否有力 |
| 大纲偏离度 | 正文事件是否与大纲对齐、章节号是否偏移、扩展/删减是否合理 |
| 角色一致性 | 角色行为是否符合其性格底色和能力设定、是否有越界行为 |
| **主题一致性（通篇）** | 核心主题是否贯穿全段所有章节、是否有反例（与主题相悖的处理）、关键角色结局是否体现主题 |


## 卷末终审模式（Volume-End Final Audit）

当用户给出「终审 chX-Y + 维度列表」形式的指令时，这是卷末终审 —— 比普通定向审查更重、更系统性。适用场景：一卷写完后的整体质量把关。

终审分两阶段执行：**先结构一致性（5维），后叙事质量（6维）**。结构一致性是基础——时间线断裂、等级倒退、金手指数值崩坏这些问题不先修，叙事审查没有意义。

### 阶段一：结构一致性审查（优先·5 维）

适用场景：重生/系统/游戏/升级流网文的基础连续性把关。**必须在叙事审查前跑完。**

#### 5 标准维度

1. **时间线连续性** — 逐章提取时间锚点（年月日/季节/早晚），检查：是否有日期倒退、是否与大纲时间设定一致、章间时间过渡是否可线性追溯
2. **等级/数值提升路径** — 逐章记录主角等级/权限/能力值。检查：等级是否单调递增（不能倒退）、升级速度是否与大纲设定一致、权限跃迁节点是否正确触发
3. **金手指使用频率与合规** — 逐章统计金手指使用次数/金币消耗/额度。对照系统设定检查：是否越级使用、是否超额使用、金币余额轨迹是否合理、是否在非必要时段滥用
4. **节奏评分（每5-10章一检）** — 每5-10章为一个区间，检查是否有明确的爽点/钩子/情感高潮。标注每个区间的最高爽点及其类型（打脸/暴富/智谋/情感/成长）
5. **大纲偏离度** — 逐章对比大纲设定的关键事件，记录：时间偏离、等级偏离、内容偏离（扩展/删减/替换），计算总体符合度百分比

#### 执行方法

```
Step A：加载设定文件（系统设定/世界观/数值体系）
Step B：加载大纲文件（总纲/卷纲/节拍表）
Step C：通读全部章节，逐章提取时间锚点+等级+金手指使用
Step D：逐章对照大纲，标记偏离
Step E：汇总为结构一致性评分表（5维×加权分）
```

#### 输出格式

```markdown
## 终审报告：ch{START}-{END} 结构一致性

### 一、逐章时间线+等级表
| 章号 | 时间锚点 | 等级 | 权限 | 关键事件 |
|------|---------|------|------|---------|

### 二、时间线连续性诊断
{列出所有时间错序、倒退、锚点缺失}

### 三、等级提升路径
{逐级提升线 + 权限跃迁检查 + 倒退/矛盾标注}

### 四、金手指使用统计
{逐章互通操作表 + 金币余额轨迹 + 合规性检查}

### 五、节奏评分
{每5-10章区间爽点/钩子检测 + 节奏曲线}

### 六、大纲偏离度检查
{逐章对比 + 重大偏离汇总 + 总体符合度%}

### 七、综合评分
| 维度 | 评分 | 权重 | 说明 |
|------|------|------|------|
| 时间线连续性 | /100 | 25% | ... |
| 等级提升路径 | /100 | 20% | ... |
| 金手指使用 | /100 | 15% | ... |
| 节奏与爽点 | /100 | 25% | ... |
| 大纲偏离度 | /100 | 15% | ... |
| **总评** | /100 | | |

### 八、修复优先级
{🔴阻塞 → 🟡建议 → 🟢可后修 三级排序}
```

#### 常见阻塞问题速查

| 问题类型 | 典型表现 | 严重度 |
|---------|---------|--------|
| 时间错序 | ch08写"十月中旬"但前文在国庆周 | 🔴阻塞 |
| 等级倒退 | ch34写29→31级但前文已32级 | 🔴阻塞 |
| 金手指越级 | L2权限带出需L4的物品 | 🔴阻塞 |
| 金币崩坏 | 余额不够解锁操作但正文写了 | 🔴阻塞 |
| 大纲事件丢失 | 大纲设定事件被跳过未写 | 🟡中度 |

### 阶段二：叙事质量审查（6 维）

结构一致性修复后，进入叙事质量审查。默认覆盖以下 6 个维度（用户可增减），**按依赖顺序执行**：

1. **战术/战斗逻辑** — 先查最硬核的事实层。检查：战术部署是否有明确计划、人数差和地形/信息差如何平衡、胜败因果是否由角色决策驱动而非巧合
2. **商业/对抗合理性** — 查商战线。检查：攻防节奏是否逐级升级、反击手段是否可操作（符合时代背景）、证据链是否闭环（谁→怎么做→结果）、是否借第三方而非自爆
3. **感情线节奏** — 查情感升温节点。特别关注：双重表白场景的衔接（前一场和后一场的关系定位是否递进、中间间隔是否合理）
4. **伏笔/铺垫升级** — 查跨章线索。用 ch→ch→ch 路径追踪检查每个伏笔的埋入→发酵→引爆链是否完整
5. **卷末牵引力** — 查下一卷势能。检查：各主线是否收束到新方向、是否埋下明确的下卷冲突种子、章末钩子是否有足够悬念密度
6. **主题一致性（通篇查）** — 最后查，因为需要前面 5 维的事实基础。检查：核心主题是否在每个关键角色弧上体现、是否有角色结局与主题相悖、显性主题句（角色笔记本/对话中的点题）是否出现在合适位置

### 主题一致性检查方法

这是终审独有的维度，普通定向审查通常不覆盖：

1. **提取主题句** — 从 `outline/` 和 `setting/` 中找出本书核心主题
2. **列举关键对手** — 列出本卷/全书所有重要对抗角色
3. **追踪转化弧** — 逐角色验证：初始状态（敌人/威胁）→ 转折点（哪章发生转变）→ 最终状态（盟友/客户/内部成员）
4. **检查反例** — 是否有角色被「消灭」而非「转化」？如有，是否为主题故意设计的对照？
5. **验证点题** — 主题句是否在正文中有显性表达（如角色内心独白、笔记本记录、对话）？点题章节是否在合适位置（通常在反转/收束章节末尾）？

输出格式：

```
| 对手 | 初始→最终 | 转化关键 | 转折章 | 评分 |
|------|-----------|---------|--------|------|
| 角色A | 敌人→盟友 | 体面的合作关系 | ch50 | ★★★★★ |
```

### 终审报告输出格式

终审报告按两阶段分别输出：

**阶段一输出**（结构一致性，见上文阶段一输出格式）

**阶段二输出**（叙事质量）：

比普通定向审查多一个 **总体评估表** 和 **主题一致性专章**：

```markdown
## 终审报告：ch{START}-{END} 叙事质量

### 一、整体评估
{2-3句总评}

### 二、分维度审查
{按 6 维逐项输出，每项 ★ + 证据引用}

### 三、主题一致性专项
{转化弧表 + 点题位置检查 + 反例检查}

### 四、总体评分
| 维度 | 评分 | 备注 |
|------|------|------|
| 战术逻辑 | ★★★★★ | ... |
| ... | ... | ... |

### 五、结论与建议
{总结 + 待处理事项 + 追踪文档更新建议}
```

**合并终审报告**（两阶段合一）：

```markdown
## 终审报告：ch{START}-{END}

### 第一阶段：结构一致性
{5维评分表 + 修复优先级}

### 第二阶段：叙事质量
{6维评分 + 主题一致性专项}

### 总评
{两阶段加权总评 + 完整修复清单}
```

### 终审后必做动作

审查完成后，必须检查并建议更新：
- `novel_project` MCP 里的伏笔实体 — 是否有新伏笔已埋入但未登记（`create_entities` 补建）
- 主角/主要配角实体 — 位置/关系是否与最新章节一致（补 `chXXX:` 观测 + `create_relations`）
- 大纲中是否有章节号偏移需要标注
