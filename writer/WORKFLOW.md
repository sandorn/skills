# Writer Skill 完整答题流程

> 从一个新选题开始，模拟使用本 skill 的端到端流程。
> 每个阶段标注用户需要说的激活词和 skill 的执行动作。

---

## 阶段一：市场调研

### 1.1 扫榜
```
用户:「最近都市重生文什么比较火」
用户:「帮我扫一下番茄排行榜」
```
> 路由: `scan.md` — 跨平台扫榜 + 趋势分析
> Skill 动作: 搜索排行榜数据，输出趋势报告（热门题材/读者偏好/竞争格局）

### 1.2 拆文
```
用户:「拆一下排行第一的那本书」
用户:「分析它的黄金三章是怎么写的」
```
> 路由: `analyze.md` — 爆款拆解 + 黄金三章分析
> Skill 动作: 读取对标书籍，输出结构拆解报告（开篇钩子/爽点分布/人设/节奏）

---

## 阶段二：项目创建

### 2.1 开新书
```
用户:「帮我开一本都市重生文，主角回到2001年开网吧」
```
> 路由: `project-init.md`
> Skill 动作:
>   1. 收集信息（书名/题材/平台/字数/章节数，未说的自动推定）
>   2. 创建目录结构（setting/ outline/ chapters/ tracking/ .writer/）
>   3. 生成 writer.json
>   4. 从 templates/project-skeleton/ 复制设定文件模板
>   5. 「下一步: plan」

---

## 阶段三：大纲规划

### 3.1 大纲
```
用户:「帮我规划大纲」
用户:「我要写三卷，每卷60章」
```
> 路由: `plan.md`
> Skill 动作:
>   1. 生成总纲（核心冲突 + 结局方向 + 暗线）
>   2. 生成卷纲（每卷节拍表 + 时间线）
>   3. 生成章纲（每章事件 + 情绪目标 + 钩子类型）
>   4. 「下一步: 批量写前跑 pre-write-alignment」

---

## 阶段四：写前检查

### 4.1 批量写前对齐
```
用户:「我要批量写10章」
用户:「写前检查」
```
> 路由: `pre-write-alignment.md`（批量必做）或 `pre-write-checklist.md`（单章30秒）
> Skill 动作:
>   1. 加载总纲→卷纲→章纲→追踪，5层递进验证
>   2. 确认当前写作位置与设计意图对齐
>   3. 交叉校验大纲 vs 追踪（等级/金币/权限/关系）
>   4. 发现问题→修正后再动笔

---

## 阶段五：写章

### 5.1 单章续写
```
用户:「写下一章」
用户:「续写第5章」
```
> 路由: `write.md`（默认5步管线）
> Skill 动作:
>   Plan → Architect → Write + Reflect → Audit + Normalize → Revise
>   写正文到 chapters/ch_005.md，同步更新追踪文件

### 5.2 批量写章
```
用户:「批量写3章」
```
> 路由: `write.md`（batch 模式）
> Skill 动作:
>   ① 预写对齐检查 → ② 子代理并行写章(≤5章/批) → ③ 委派返回后质检+修复

### 5.3 短篇
```
用户:「写个短篇故事」
```
> 路由: `write.md`（short 模式）
> Skill 动作: 情绪目标→构思→结构→写作→审查→润色

---

## 阶段六：审查

### 6.1 日更发布前审查
```
用户:「审查一下今天写的」
用户:「daily」
```
> 路由: `review.md`（daily 模式 — 8维 3分钟）
> Skill 动作:
>   检查 B01-B05禁令 → 字数≥2500 → 段落≤42 → AI高频词 → 章末钩子 → 设定冲突 → OOC → 引号
>   全部通过 → 可发布

### 6.2 常规审查
```
用户:「审查一下最近5章」
```
> 路由: `review.md`（solo 模式 — 15维）
> Skill 动作: 15维核心检查 + AI痕迹 + 硬禁令

### 6.3 深度审查
```
用户:「深度审查前十章」
```
> 路由: `review.md`（lean 模式 — 27维）

### 6.4 全面审查
```
用户:「全面审查」
用户:「全量审查第一卷」
```
> 路由: `review-cycle.md`（5步管线）
> Skill 动作:
>   Step 0 体检 → Step 1 粗筛 → Step 2 深筛(43维, 4Agent并行) → Step 3 终验 → Step 4 追踪+事实库 → Step 5 全景报告

### 6.5 定向审查
```
用户:「帮我审查一下攻城战攻城战的商业逻辑」
用户:「专项审查感情线节奏」
```
> 路由: `targeted-audit.md`
> Skill 动作: 用户指定维度 → 标准化评分 → 大纲正文对照 → 输出★1-5评级报告

### 6.6 逐章通读
```
用户:「逐章检查，不用脚本」
用户:「一章一章过」
```
> 路由: `review.md`（manual-pass — 零脚本/零子代理）
> Skill 动作: 主会话逐章通读 → 语调评价 + 问题列表 + 修复操作

---

## 阶段七：质检与修复

### 7.1 质检
```
用户:「质检」
用户:「全线检查一下」
```
> 路由: `quality.md`（5步）
> Skill 动作:
>   Step 1 禁令扫描(audit.py) → Step 2 字数/段落修复 → Step 3 审查 → Step 4 去AI味 → Step 5 验证

### 7.2 去AI味
```
用户:「这章太AI了」
用户:「去AI味」
```
> 路由: `quality.md`（deslop 模式）
> Skill 动作: 6 Gate 逐项清除（禁用词→句式→心理外化→节奏→对话→结尾）

### 7.3 修复
```
用户:「帮我修一下」
用户:「审查发现的问题修一修」
```
> 路由: `post-review-fix.md`（判定）→ `quality.md`（执行）
> Skill 动作:
>   S1阻塞 → 走 quality.md 五步强制管线
>   S2/S3问题 → 四步精准修复

---

## 阶段八：润色

### 8.1 批量文风转换
```
用户:「帮我把这些章节转成番茄风」
用户:「批量润色」
```
> 路由: `style-transfer.md` → `polish.py`
> Skill 动作: API批量润色（输出到独立目录，不覆盖源文件）

### 8.2 纯手动精修
```
用户:「纯手动润色」
用户:「逐章逐段手工打磨」
```
> 路由: `manual-polish.md`（三零原则）
> Skill 动作:
>   零脚本/零子代理/零批量替换 → 主会话逐章通读 → 逐句微调 → 一章一结

## 阶段十：持续维护

### 10.1 开新卷
```
用户:「开第二卷」
用户:「进入下一卷」
```
> 路由: `deploy.md`
> Skill 动作: 卷间衔接检查(7维) → 节拍表 → 批量写章部署

### 10.2 状态查询
```
用户:「项目什么状态了」
用户:「全景报告」
```
> 路由: `report_panorama.py`
> Skill 动作: 生成项目全景报告（健康评分/章节统计/设定文件状态/建议）

### 10.3 数据查询
```
用户:「查一下主角现在的等级」
用户:「伏笔回收了哪些」
```
> 路由: `fact_db.py query`
> Skill 动作: 查询 facts.db 返回结构化数据

### 10.4 节奏分析
```
用户:「最近节奏怎么样」
用户:「升级是不是太慢了」
```
> 路由: `analyze_rhythm.py`
> Skill 动作: 等级/金币/感情线/钩力趋势聚合报告

### 10.5 追读力分析
```
用户:「追读力怎么样」
用户:「钩子强度够不够」
```
> 路由: `analyze_hook.py`
> Skill 动作: 钩子强度/爽点分布/钩力衰减报告

### 10.6 关系图谱
```
用户:「角色关系图谱」
用户:「谁和谁什么关系」
```
> 路由: `report_graph.py`
> Skill 动作: 生成 Mermaid 格式实体关系图

### 10.7 设定审计
```
用户:「帮我审查设定是不是前后矛盾」
```
> 路由: `setting-consistency-audit.md`
> Skill 动作: 设定内部→大纲→正文→卷间→修复，五层审计

### 10.8 角色状态更新
```
用户:「更新角色状态」
```
> 路由: `track-character-state.md`
> Skill 动作: 全量/增量更新 tracking/current_state.md

### 10.9 长篇质量
```
用户:「检查一下有没有声音漂移」
```
> 路由: `longform-quality-monitor.md`（>100章时）
> Skill 动作: 跨章节采样对比（句长/感官密度/对话模式/段落呼吸/结尾风格）

### 10.10 故障排除
```
用户:「报错了」
用户:「不工作了怎么办」
```
> 路由: `troubleshooting.md`
> Skill 动作: 诊断写章/审查/委派/修复四场景常见故障

## 完整流程速查

```
选题阶段:     扫榜 → 拆文
              「什么火」「拆一下」

项目创建:     开新书
              「帮我开一本XX文」

规划阶段:     大纲 → 写前检查
              「规划大纲」「写前检查」

写作阶段:     写章（单章/批量/短篇）
              「写下一章」「批量写3章」

审查阶段:     审查（daily/solo/lean/full/定向/逐章）
              「daily」「全面审查」「逐章检查」

质检阶段:     质检 → 去AI味 → 修复
              「质检」「太AI了」「修一下」

润色阶段:     批量转换 / 纯手动
              「转成番茄风」「纯手动润色」

发布阶段:     番茄检查 → 导出 → 封面 → 备份
              「番茄投稿检查」「导出」「备份」

持续维护:     开新卷 / 状态查询 / 数据分析 / 故障排除
              「开第二卷」「全景报告」「追读力怎么样」
```
