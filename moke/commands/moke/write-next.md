Execute the complete MoKe 9-step pipeline: plan → compose → architect → write → observe → reflect → normalize → audit → revise (if needed).

</objective>

<process>
## MoKe 完整 9 步管线流程

每一章由 9 个 Agent 接力完成，全程零人工干预：

### 管线步骤（与 InkOS 对齐）

#### 步骤 1/9：规划章节 (moke:planner)
**作用**：生成章节意图声明

**输入**：
- 作者意图 (`story/author_intent.md`)
- 当前焦点 (`story/current_focus.md`)
- 当前状态 (`story/current_state.md`)
- 伏笔池 (`story/pending_hooks.md`)
- 卷纲 (`story/volume_outline.md`)
- 额外创作指导（可选，来自 --context 参数）

**输出**：
- `runtime/chapter-XXXX.intent.md` - 章节意图声明（机器可读）
- `runtime/chapter-plan.md` - 详细规划（人类可读）

**产出内容**：
- 核心目标 (core_objective)
- 必须保留 (must_keep)
- 必须避免 (must_avoid)
- 主冲突 (primary_conflict)
- 次冲突 (secondary_conflict)
- 伏笔计划 (foreshadowing: plant/advance/resolve)

#### 步骤 2/9：编排上下文 (moke:composer)
**作用**：从全量真相文件中按相关性选择上下文，编译规则栈

**输入**：
- 章节意图（来自 Planner）
- 所有 7 个真相文件
- 世界观设定 (`story/story_bible.md`)
- 本书规则 (`story/book_rules.md`)
- 25 条通用创作规则

**输出**：
- `runtime/chapter-XXXX.context.json` - 精选上下文数据
- `runtime/chapter-XXXX.rule-stack.yaml` - 规则优先级层
- `runtime/chapter-XXXX.trace.json` - 结构规划轨迹
- `runtime/context.md` - 人类可读上下文

**产出内容**：
- 相关角色列表
- 相关位置和场景
- 活跃支线和伏笔
- 规则栈（通用 → 题材 → 书级）

#### 步骤 3/9：规划结构 (moke:architect)
**作用**：规划章节结构，设计场景节拍和节奏

**输入**：
- 章节规划（来自 Planner）
- 上下文包（来自 Composer）
- 当前状态
- 世界观设定

**输出**：
- `runtime/structure.md` - 人类可读结构设计
- 更新 `runtime/chapter-XXXX.trace.json` - 结构决策记录

**产出内容**：
- 场景划分（每个场景的位置、角色、字数分配）
- 节奏控制（开场/发展/高潮/结尾）
- 场景转换逻辑
- 情感节奏设计

#### 步骤 4/9：写作正文 (moke:writer)
**作用**：基于编排后的精简上下文生成正文

**输入**：
- 章节意图（来自 Planner）
- 上下文包（来自 Composer）
- 结构设计（来自 Architect）
- **所有 7 个真相文件**（智能过滤）

**7 个真相文件**：
1. `story/current_state.md` - 当前状态卡
2. `story/particle_ledger.md` - 资源账本（如有数值系统）
3. `story/pending_hooks.md` - 伏笔池
4. `story/chapter_summaries.md` - 章节摘要
5. `story/subplot_board.md` - 支线进度板
6. `story/emotional_arcs.md` - 角色情感弧线
7. `story/character_matrix.md` - 角色交互矩阵

**智能过滤逻辑**：
- 识别相关角色：主角 + 本章规划中的角色 + 当前位置在场角色
- 加载相关内容：相关角色的位置/关系/情感、活跃支线、待推进伏笔
- 控制上下文长度：按相关性排序，优先级为当前位置 > 相关角色 > 活跃伏笔 > 支线进度

**输出**：
- `chapters/第N章-<标题>.md` - 完整章节内容
- 字数达标（3000±200字）
- 格式规范的 Markdown

**25 条通用创作规则（与 InkOS 一致）**：

**人物塑造铁律（5条）**：人设一致性、人物立体化、拒绝工具人、角色区分度、情感/动机逻辑链

**叙事技法（7条）**：Show don't tell、五感代入法、钩子设计、对话驱动、信息分层植入、描写服务叙事、日常段落服务剧情

**逻辑自洽（5条）**：三连反问自检、信息越界检查、关系改变事件驱动、场景转换过渡、每段带来新信息

**语言约束（5条）**：句式多样化、词汇控制、群像反应具体化、情绪细节传达、禁止元叙事

**去AI味铁律（5条）**：叙述者不下结论、禁止分析报告式语言、转折标记词限制、意象渲染限制、心理分析术语禁入正文

**硬性禁令（最高优先级）**：
- 禁止"不是……而是……"句式
- 禁止破折号"——"
- 禁止正文中的 hook_id/账本式数据

**规则优先级**：
1. 硬性禁令（最高）
2. 题材规则
3. 书级规则
4. 通用规则（25条，基础）

**输出**：
- `chapters/第N章-<标题>.md` - 完整章节内容
- 字数达标（3000±200字）

#### 步骤 5/9：提取事实 (moke:observer)
**作用**：从正文中提取 9 类事实

**输入**：
- 章节内容
- 章节编号和标题

**输出**：
- `runtime/observations.md` - 观察记录

**提取的 9 类事实**：
1. **角色行为** - 谁做了什么，对谁，为什么（含场景标注）
2. **位置变化** - 谁去了哪里，从哪里来（场景转换）
3. **资源变化** - 获得、失去、消耗了什么（具体数量）
4. **关系变化** - 新相遇、信任/不信任转变、结盟、背叛
5. **情绪变化** - 角色情绪从 X 到 Y（触发事件）
6. **信息流动** - 谁知道了什么新信息，谁仍不知情
7. **剧情线索** - 新埋、推进、回收伏笔
8. **时间推进** - 过了多长时间，时间标记
9. **身体状态** - 受伤、恢复、疲劳、战力/修为变化

#### 步骤 6/9：更新状态 (moke:reflector)
**作用**：将观察结果合并到 7 个真相文件

**输入**：
- 观察记录（来自 Observer）
- 当前真相文件内容
- 章节编号

**输出**：
- 更新所有 7 个真相文件
- `runtime/state-changes.md` - 状态变更汇总

**增量更新机制**：
- 新增伏笔 → 添加到 pending_hooks.md
- 推进伏笔 → 更新 pending_hooks.md 状态
- 回收伏笔 → 标记已回收，记录解答章节
- 更新状态 → 同步更新 current_state.md、character_matrix.md 等
- 保持格式 → 维护 markdown 格式
- 时间戳 → 在变更处标注章节号 `[第N章]`
- 冲突检测 → 发现矛盾时标记为需要人工确认

#### 步骤 7/9：字数归一 (moke:normalizer)
**作用**：单 pass 压缩/扩展，将章节字数拉入允许区间

**输入**：
- 章节内容
- 当前字数
- 目标字数范围（2800-3200 字）
- 章节意图（用于保持内容完整性）

**输出**：
- 更新章节文件
- 字数归一化报告

**修正模式**：
- **压缩模式**（字数 > 3200）：删除冗余描述、合并相似场景、精简对话
- **扩展模式**（字数 < 2800）：增加场景细节、扩展对话、添加心理描写
- **安全阈值**：归一化后字数不得低于原字数的 25%

#### 步骤 8/9：审计质量 (moke:audit)
**作用**：对照 7 个真相文件验证草稿

**输入**：
- 最新章节内容
- 7 个真相文件
- 规则栈

**输出**：
- `runtime/audit-report.md` - 审计报告

**33 维度质量检查**：
- 连续性检查（角色、位置、关系、时间）
- 角色一致性（OOC 检测）
- 逻辑合理性（行为动机、信息边界）
- 字数检查（是否在允许区间）
- 伏笔管理（是否推进/回收）
- 规则符合性（25 条通用规则 + 题材规则 + 书级规则）
- AI 痕迹检测（转折标记词、分析报告式语言）
- 敏感词检测

#### 步骤 9/9：修订问题 (moke:revise)
**作用**：修复审计发现的问题

**输入**：
- 审计报告
- 待修订章节
- 问题列表

**输出**：
- 更新章节文件
- 修订报告

**修订模式**：
- **spot-fix**（定点修复）：修复关键问题
- **polish**（润色）：优化表达
- **rewrite**（改写）：重写有问题的段落
- **rework**（重写）：大幅重写
- **anti-detect**：去除 AI 痕迹

**循环逻辑**：
- 如果审计不通过，进入"修订 → 再审计"循环
- 直到所有关键问题清零
- 最多循环 3 次

### 后写校验步骤（与 InkOS 一致）

在章节正式保存前，必须进行以下后写校验：

**硬性禁令检查**：
- 检查是否包含"不是……而是……"句式
- 检查是否包含破折号"——"
- 检查正文是否包含hook_id或账本式数据
- 如发现违规，立即修正

**创作规则符合性检查**：
- 人设一致性：所有角色行为是否符合其性格底色和动机
- 信息边界：反派行为是否基于其已知信息
- 逻辑自洽：场景转换是否自然，关系改变是否有事件驱动
- 去AI味：转折标记词是否超标，是否出现分析报告式语言

**字数和结构检查**：
- 字数是否在允许区间内（2800-3200字）
- 是否包含章节结尾钩子
- 对话/叙述比例是否合理

### 循环逻辑

如果审计不通过，管线自动进入"修订 → 再审计"循环，直到所有关键问题清零。

### 运行时产物（与 InkOS 对齐）

每章必须生成 4 个运行时产物文件：

1. **`runtime/chapter-XXXX.intent.md`** - 章节意图声明
   - 核心目标、必须保留/避免、冲突设计、伏笔计划

2. **`runtime/chapter-XXXX.context.json`** - 精选上下文数据
   - 相关角色、位置、支线、伏笔
   - 当前状态快照

3. **`runtime/chapter-XXXX.rule-stack.yaml`** - 规则优先级层
   - 通用规则（25条）
   - 题材规则（按题材加载）
   - 书级规则（覆盖）

4. **`runtime/chapter-XXXX.trace.json`** - 结构规划轨迹
   - 结构决策记录
   - 场景划分和字数分配

### 后写校验（与 InkOS 一致）

每章完成后执行后写校验：

**校验 1：运行时产物完整性检查**
- 检查 4 个运行时产物文件是否全部存在

**校验 2：规则栈验证**
- 验证优先级无冲突
- 验证通用规则（25条）已应用
- 验证书级规则覆盖正确

**校验 3：上下文一致性**
- 验证上下文包含必要信息（角色、位置、支线）
- 验证与意图的对齐

**校验 4：轨迹完整性**
- 验证轨迹包含关键决策记录
- 验证场景记录完整

### 配置选项

管线行为受 `books/<书名>/.moke/config.json` 中的设置控制：

- **mode**: `yolo`（全自动）或 `interactive`（每步确认）
- **modelProfile**: `quality`/`balanced`/`budget`（控制各 agent 使用的模型）

### 输出

1. 章节文件：`books/<书名>/chapters/第N章-<标题>.md`
2. 观察记录：`runtime/observations.md`
3. 状态变更：`runtime/state-changes.md`
4. 审计报告：`runtime/audit-report.md`

### 使用方式

```bash
# 使用默认设置
/moke:write-next

# 写多章
/moke:write-next --count 3

# 带上下文指导
/moke:write-next --context "本章重点描写师徒矛盾"
```
</process>
